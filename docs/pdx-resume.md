# 完整包与补丁下载暂停与恢复 · 0.20.0

IRONCLAD在0.7.0实现自有HOI4完整ZIP暂停与恢复，0.19将同一机制用于独立签名补丁，分开目标完整包、实际传输包与差分旧源。0.20进一步允许空operations补丁的已签名展开量为0，暂停重开后仍恢复同一补丁并复制可信旧ZIP。实际执行范围见 [规划底座与单ZIP子集](pdx-patch-planning.md)、[增量下载与缓存](pdx-delta-core.md) 和 [补丁选择](cpatch-download-paths.md)；通用多目标计划不改变恢复权限。它不读取或伪造官方CPatch暂停记录，官方内部断点/缓存格式兼容仍未实现；最终验证以 [Roadmap](../ROADMAP.md) 和对应证据为准。

## 用户行为

等待元数据或下载过程中可以暂停；补丁应用与安装阶段不能暂停。暂停后释放账号会话和运行保护，原有安装仍可用。继续下载重新检查游戏状态、目录、元数据、签名及权限；固定版本不变，账号模式重新绑定当前登录。已选版本差分还须重新取得同一旧源计划并打开可信原 ZIP 缓存；缺失、损坏或变化时保留片段并停止，不能静默改取目标 complete。重开启动器只显示可恢复状态，不自动发起内容请求。

任务暂停或持有断点时，先继续或取消，再开始另一项下载。取消仅清理能够确认归属的片段；身份、内容或未知尾部发生变化时保留路径，不删除用户可能修改的文件。限速可以在暂停时调整。

## 持久化与磁盘顺序

下载记录使用 v2，兼容读取 v1。v1 没有校验记录的临时文件保留，不直接用于续传。记录包含当前任务、限速、暂存位置和 `partial={plan,transferPlan?,sourcePlan?,checkpoint,userDataPath}`；复制旧片段时额外保存 resumeSource。`plan` 始终是目标 complete，`transferPlan` 是已选补丁，`sourcePlan` 是版本差分旧 complete；`-1` 安装补丁没有旧源计划。账号 ID、token、Cookie、授权 URL、缓存 handle 和不可序列化的可信能力不写入下载记录。

checkpoint包含版本、实际 `transferPlan || plan` 的规范计划摘要、已保存字节数、前缀SHA-256、可用的强ETag，以及文件与祖先目录身份。补丁的 `kind/fromRevision/unpackedBytes` 参与计划绑定，`unpackedBytes:0` 是有效且必须保留的精确值，不表示目标ZIP或传输包为0字节。补丁片段保存为 `patch.zip`，完整包片段为 `content.zip`，两者不能互用。传输层在同步磁盘后等待协调器持久化checkpoint；写入记录失败时停止传输，不能显示为暂停成功。暂停最终显示已保存字节数和零传输速度，避免写入瞬间的进度落后。

恢复时先重新授权、验签并核对目标与实际传输计划，版本差分另核对旧源计划和原 ZIP 缓存；补丁或旧源身份变化即停止。随后新建独占目标文件，验证旧片段身份和前缀摘要后复制可信字节。旧片段只读，即使崩溃后有未登记尾部也不截断。新片段至少达到旧进度且保存成功后，才能清理已确认的旧片段；无法确认的旧文件列出保留位置。复制中断时仍能选回较完整的旧 resumeSource。片段选择只保存一次合法状态，未生成断点的新副本记入保留路径；即使紧接着再次崩溃或无法写盘，重启仍可恢复或取消。

## HTTP 与完整性

从实际传输包的已保存位置请求 `Range: bytes=N-`，有强 ETag 时同时发送 `If-Range`。没有强 ETag 时仍受重新验签的精确 manifest SHA-256 约束。206 必须返回匹配的起点、终点、总长、长度和校验器；内容编码必须是 identity。匿名请求使用固定 CDN，受保护请求使用独立资源授权返回且通过校验的 HTTPS 内容地址；内容主机不接收账号凭据，也不跟随重定向。

服务器返回 200 时，只清空新建传输文件并从头下载**同一传输包**，界面显示范围续传回退提示；不会把完整响应追加到旧片段后，也不会把已选补丁换成目标 complete。416、错误范围或校验器不匹配不能当作完成。片段已覆盖全部传输长度时重新校验整包，可不再请求该归档。

最终对传输文件重新计算完整SHA-256。完整包验证成功后交给原安装事务；补丁验证成功后，在安全工作区重建目标 `content.zip`，目标长度、累计摘要和fsync后落盘重读摘要均匹配目标complete才安装。当前单ZIP允许一个d加一个n/p/k，空operations或仅d须复制与目标一致的可信旧ZIP，无源p使用0字节空源；这些情况均不能跳过实际源/目标摘要检查。d只作用于新空目标的逻辑阶段，不删除旧缓存或旧安装。选定补丁后的签名、权限、传输、容器、旧源或目标错误停止，不静默改取complete。安全工作区证明经持久化并由清理器独立复核后，才允许清理已知派生文件；未知、取消/崩溃遗留或外部变化的内容保留。

暂停、网络错误及重启恢复都不能跳过整包校验。取消或账号失效优先于暂停；安装已经提交时以原事务的最终结果为准。

## 验证入口

- tests/pdx-transfer.test.cjs：传输、范围、校验、身份和异常边界。
- tests/pdx-resume-jobs.test.cjs：协调器与持久化、账号重绑、源选择与故障落盘边界。
- tests/pdx-authorized-download.test.cjs：挂起 CDN 流期间退出、重新登录、过期会立即中断；保留可信断点，只有显式继续才重新授权并安装。
- tests/pdx-resume-integration.test.cjs：真实本机 HTTP 流，暂停后重开、206 续传、200 回退和未知尾部保留。
- [tests/pdx-patch-integration.test.cjs](../tests/pdx-patch-integration.test.cjs)：生产签名验证器与隔离内容，补丁/旧源重新验签、精确恢复、拒绝计划变化及失败降级；0.20新增空operations/展开量0补丁在64字节暂停，服务重开不联网，显式继续发送 `Range: bytes=64-` 后安装并验证完整。
- [tests/pdx-patch-workspace.test.cjs](../tests/pdx-patch-workspace.test.cjs) 和 [清理测试](../tests/pdx-patch-cleanup.test.cjs)：稳定文件访问、完整重读、并发证明、取消、关闭与未知派生文件保留。
- scripts/test-pdx-resume-ui.mjs：无界面 Edge，真实后台服务与隔离游戏目录，验证按钮、重开、安装及预设保留。
- scripts/smoke-desktop.cjs：已扩展隐藏 Electron 场景；0.7 的启动曾被自动审批拒绝，返回 blocked by policy。该历史记录不是新版运行通过证据；当前 Electron 验收状态见 [Roadmap](../ROADMAP.md)，无界面浏览器不能代替 Electron 验收。

以上自动化入口使用新建隔离夹具，不使用真实游戏、账号或 Steam SDK；“真实本机 HTTP”指本地服务流，不是官方 CDN。早期静态/HEAD 证据仅证明公开服务器声明 Accept-Ranges，不能据此声称真实 CDN 的 206、账号或游戏验收已通过；后续真实资源验证范围及证据以 [Roadmap](../ROADMAP.md) 为准。

0.19后续真实安装补丁重建的ZIP也通过生产安装器的隔离安装；8,155个文件及注册在提交后和服务重建后两次完整验证均通过，原ZIP不变，见 [安装报告](../test-results/official-install.json)。这是历史正常服务重开检查，未模拟进程重启、崩溃、真实协调器或CDN Range续传，不计作0.20重跑。

0.19另有真实公开 `-1_to_3` 安装补丁独立补核：完整取得559,180,000字节补丁，生产验签器验证后，生产容器实际执行n，重建目标561,485,374字节并匹配可信complete摘要，工作区 `finish/proofs` 通过。见 [原始报告](../test-results/official-install-patch.json) 与 [官方安装补丁验收](official-install-acceptance.md)。该次不使用实际下载协调器，也不证明真实CDN暂停/206、进程重启、崩溃恢复或账号通过。0.20隔离夹具中的服务重开/Range检查也不扩展到这些真实运行结论。通用c/s、多目标文件系统执行、实际k、官方内部断点/缓存及Electron、游戏、Steam等仍待完成。
