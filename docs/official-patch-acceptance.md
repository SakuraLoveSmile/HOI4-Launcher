# 官方 HOI4 大 ZIP 差分验收 · 2026-10-29

0.19.0 交付后，使用匿名公开资源补验生产签名、原始 ZIP 缓存、补丁容器、VCDIFF/XZ 和安全工作区。未修改业务代码或重新生成便携包；这份补核补充原交付时仅有隔离夹具与真实小段交叉验证的证据。

仓库固定为 `hoi4/6cca83a0-a6ec-11f1-92e5-affbeaa2abe2/repo/Any__Any/`。每组均重新读取旧版 complete、目标 complete 和补丁 manifest，使用生产验证器、固定官方根和当次撤销查询完成签名验证，再按可信字节数和 SHA-256 校验下载。源和目标完整包的摘要不同，不能以相同大小代替内容验证。

第一组从官方 CDN 读取旧版 ZIP 和补丁 ZIP；完整目标正文没有另行下载。原始 ZIP 经生产缓存的 `put/open` 完整校验和稳定 handle 后作为差分源。生产容器校验外 ZIP、展开大小、CRC、唯一 `p` 操作及 payload，再由 VCDIFF/XZ 解码、逐窗校验和最终目标重读完成验证。工作区 `finish()` 同步并重读文件，`proofs()` 再核对全部固定文件的摘要与身份。上述目标与独立验签的官方 complete 清单完全一致。容器执行至完成并产生最终证明共 257,101 ms，不包括最初源下载和缓存准备。

第二组复用第一组通过证明的目标 ZIP，重新验签旧版/目标/补丁并建立稳定源缓存，用实际 4,822,405 字节补丁重建版本 5；68 个窗口、568,391,768 字节目标及完整摘要均通过相同的生产校验与工作区证明。重建阶段为 306,894 ms，同样不包括前置缓存准备。这增加了真实压缩数据的覆盖，未另取完整目标正文。

脚本为 [.work/verify-official-patch.cjs](../.work/verify-official-patch.cjs)，首次日志和报告分别为 [official-patch-acceptance.txt](../test-results/official-patch-acceptance.txt) 与 [official-patch-acceptance.json](../test-results/official-patch-acceptance.json)，第二组报告为 [official-patch-follow-on.json](../test-results/official-patch-follow-on.json)。大型源、缓存和重建 ZIP 保存在报告所列项目内隔离目录，未安装或打开。两组原始清单、签名、补丁、日志、模块及文档快照归档于 [补核汇总](../test-results/official-patch-acceptance-2026-10-29/verification-summary.json)；大型文件另行独立重算大小和 SHA-256，不在证据目录重复保存。

## 适用范围

上述两组 `p` 的原始结果和归档保持不变。后续另行补验同仓库真实 `-1_to_3` 的 `n` 安装补丁，目标与本页版本 3 的 complete 摘要相同；独立报告及安装边界见 [安装补丁与隔离安装验收](official-install-acceptance.md)。后续结果不追溯计入本页两次执行。

这是实际官方 ZIP 字节到实际目标 ZIP 的验收，使用系统 Node 和当前生产模块。脚本固定公开仓库路径，未调用真实账号、Steam SDK、游戏、官方 CPatch/xdelta3、Electron 或便携程序，也未写入玩家目录或操作前台窗口。它没有运行下载协调器/安装器的真实端到端流程；后者的事务、账号变化和续传证据仍来自原有隔离整合测试。

通过一组或多组真实 `p` 差分不能证明所有官方版本、所有编码器参数、安装补丁 `n`、旧源复制 `k` 或通用 `c/d/s` 都已在真实服务验收。通用多操作与内部缓存/断点格式仍不支持；不能据此宣称完整 CPatch 兼容。当前支持的单 ZIP 操作及失败条件见 [增量下载](pdx-delta-core.md)。

官方 HOI4 发布链的单 ZIP 依据及三个额外已验签仓库抽样见 [容器范围研究](../.work/hoi4-container-scope.md)。该研究说明已观察到的发布和消费方式；原始响应未完整保存的抽样明确不能离线重放，也不证明所有历史或未来 HOI4 仓库都相同。它不删除未验收要求或把通用引擎能力当作 HOI4 当前已启用功能。
