# 启动器更新

设置页的启动器更新只读取 `SakuraLoveSmile/HOI4-Launcher` 的最新正式 GitHub Release。草稿、预发布和版本号无效的发布不会用于自动更新；版本不高于当前版本时不提供下载安装。检查失败、没有 Release、GitHub 限流或网络超时会显示错误，可以重试或打开发布页面。

0.28.0 作为在线更新的起始版本，首次需要手动下载并运行该便携包；后续正式版本可以从设置页安装。0.27.0 及更早版本没有在线更新入口。

## 发布约定

每个正式 Release 应附带两个资产：`IRONCLAD-<版本>-portable.exe` 和 `updater.json`。本地先运行 `npm run package`，再运行 `npm run update:manifest`，从已打包文件生成校验清单，格式为 `{schema:1,version,asset,size,sha256}`；也可直接运行 `node scripts/create-update-manifest.cjs`。下载同时核对清单、Release 文件名、版本和字节数，并流式计算 SHA-256；有 GitHub 的 `sha256:` 资产摘要时也核对该摘要。没有清单但有 GitHub SHA-256 摘要的版本仍可下载；两者都没有时只提供发布页入口。下载过程中可以取消，失败或取消的临时文件不会用于安装。

仓库内 `.github/workflows/release.yml` 在推送与 package.json 版本一致的 `vX.Y.Z` 标签时运行测试、构建便携包、生成清单，再创建 Release。首次启用需要将代码和工作流提交到该 GitHub 仓库，完成首次正式发布后才有可更新版本；本地改动不会自动推送、打标签或发布。

## 便携版安装

只有打包的 Windows 便携版且存在 `PORTABLE_EXECUTABLE_FILE` 时支持原位替换；开发模式和其他运行方式可检查和下载，需从发布页手动安装。安装前主进程须确认游戏及文件操作已结束。更新包在安装前再次校验，并先复制到原便携程序旁边，提前检查目标目录可写。

确认“安装并重启”后，隐藏的 PowerShell 助手等待当前启动器进程退出，重新核对原程序和更新包 SHA-256，将旧程序保留为同目录 `.backup-<UUID>` 文件，再替换并重新启动。替换或启动请求失败时尝试恢复旧程序；若无法恢复，保留文件和日志供人工恢复。助手日志存于启动器数据目录的更新缓存中。用户设置、模组、项目和游戏文件不参与替换。助手能确认进程启动请求成功，不能判断新版后续运行是否健康；旧程序备份始终保留。

这提供下载完整性校验，不替代代码签名；发布仓库和 Release 权限仍是更新信任边界。自动化测试使用隔离目录、模拟网络和模拟进程，不会替换正在运行的用户程序，也不会发布真实 Release。

## 0.28.0 验证

全量 Node 测试 1611/1611 通过，其中更新服务 30 项、实际 PowerShell 助手隔离执行 6 项。助手使用普通文本代替程序，模拟全部进程查询和启动，实际验证文件替换、备份、失败恢复、哈希拒绝及日志失败不回滚；通过 .NET 直接计算 SHA-256，避免受继承的 PowerShell 模块路径影响。
