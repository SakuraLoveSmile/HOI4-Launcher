# 模组依赖误报修复 · 0.25.2

当作者在描述文件中列出用于兼容或排序的模组名称时，旧版会把未启用的名称全部报告为“依赖未启用”。例如 [FPS BOOSTER - CPU & AI LITE](https://steamcommunity.com/sharedfiles/filedetails/?id=3766377228) 的 Steam 页面没有列出 Required Items，说明兼容多个大型模组并建议放在播放集底部，但本地 `descriptor.mod` 的 `dependencies` 包含 50 项。旧逻辑因此把未启用的大型模组也当成必需前置。

描述文件的名称列表不足以区分实际前置与排序、兼容关系。0.25.2 在总览、模组库、当前播放集和详情中取消这种推断警告；详情以“加载顺序参考”原样列出声明，并提示核对作者说明。空列表显示“未声明加载顺序”，不声称没有必需前置。新增文案覆盖全部 12 种界面语言。

## 数据和启动行为

`dependencies` 数组、作者名称和原始描述文件完整保留，显示别名仍只影响界面。后台为兼容旧状态消费者保留空的 `missingDependencies` 数组，不再通过“描述文件名称减去启用名单”生成未核实的警告。本次未新增在线 Required Items 查询或依赖解析，不能把无警告理解为所有实际前置已通过验证。

扫描、切换或编辑播放集不改写模组描述文件。启动时生成的受管描述文件仍保留原始声明，播放集顺序和启用状态不变；真正被选中但缺失的内容、无法核实的 Paradox 固定版本以及损坏的项目快照仍按原有规则阻止启动。

只读对照官方 Paradox Launcher v2026.12 的本机实现也确认，其缺依赖逻辑使用单独的结构化 `dependenciesList`／远程标识；与这里扫描到的描述文件名称数组不是同一种数据。当前 Steamworks.js 接口没有暴露完整必需项目 ID 列表，因此本次不以名称或数量猜测真实依赖。

## 验证

- 使用报告中 Mod 的实际 50 项声明作为隔离夹具。修复前，未注册 Steam、已注册 Steam、本地和 Paradox 四种扫描来源全部复现；修复后均通过，并覆盖已启用、停用和未安装参考项共存的情况。
- Node 全量 1360/1360 通过，包含真实缺失成员及固定版本保护、启动时保留原始声明，以及全部语言目录检查。
- 独立无界面 Edge：播放集 40 项、右键菜单 41 项、常规界面 54 项通过。新增检查涵盖总览、双栏、详情中性说明及空声明，不出现旧黄色警告；修改显示别名后仍保留原始声明名称。
- 隐藏 offscreen Electron 检查通过，使用生产沙箱 preload；构建和修改文件格式检查通过。
- 对本机 391 个 Mod 用旧版与修复后的服务只读对照：149 项原本会仅凭描述文件得到未启用依赖标记，其中当前启用 11 项。修复后不再生成这些未经核实的标记；所有其他扫描元数据和配置完全一致。示例 Mod 的 50 项声明完整保留，原描述文件 SHA-256 不变。此数量不表示这 149 个 Mod 都没有实际前置。

结果及便携包校验见 [0.25.2 汇总](../test-results/0.25.2/verification-summary.json)，界面截图为 `test-results/0.25.2/load-order-detail.png`。首次新增界面测试误用了关闭按钮名称，在三项新增行为断言均通过后等待超时；仅修正测试选择器后，40 项全部通过。未运行真实游戏、Steam SDK 或修改真实播放集。
