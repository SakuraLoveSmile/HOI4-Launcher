# Paradox 完整包签名验证 · 0.16.0

公开与账号授权的完整 ZIP 下载均强制通过官方 CPatch 的 OpenPGP 信任链。`repository.json` 与 `manifest` 各自具有分离签名，验证原始字节后才解析；ZIP 本身仍按已验证 manifest 的 SHA-256 和大小校验。0.16 在此基础上增加受管安装的逐文件校验与固定 revision 修复；该能力不包含增量补丁、官方 `files/` 下载、单文件网络修复或内部缓存兼容。

## 信任与旧密钥兼容

`electron/keys/pdx-production-root.asc` 固定生产公钥，主钥指纹必须为 `AF28077C9C565B53F3CD5A65788AA56D99D64E1C`。不接受 sandbox 或下载到的任意自签根。仓库公钥必须有该根对用户身份的有效认证，保持自认证、签署权限、子钥绑定及背签检查。

真实官方根在 2019-05-08 到期，仓库钥在 2020-10-08 到期，当前公开内容签名产生于 2026 年。官方 CPatch 对 `key expired` 有专门兼容处理；本实现只容忍已经验证的链中精确的主/子钥到期结果，并返回内部 `legacyExpiredKeys` 标志。密钥创建时间、内容与认证签名的未来日期/签名有效期、自认证、签署权限、撤销等其他错误继续拒绝。不能把这条链描述成“未过期”。

使用未修改的 `openpgp@6.3.2`，每次验证使用局部配置，不修改进程全局策略。SHA-1 仅用于已固定根链的旧密钥认证；内容只接受 binary 分离签名和 SHA-256/384/512。低层签名包 API 用于隔离官方所需的密钥到期例外，同时显式保留日期与权限检查；不以 `date:null` 全局关闭内容验签。多实体公钥、额外签名包、伪造或过大的 armor 均拒绝。

## 撤销与网络边界

每次解析下载计划都重新取得仓库公钥、两份原始文档与签名，并查询生产根和仓库钥的撤销状态。没有钥缓存或离线撤销状态缓存，因此不需要在旧缓存验签失败后重试；新请求直接使用当次取得的钥。重开与手动续传仍重新执行全部步骤。

撤销地址固定为 `https://revocation-prod.paradox-interactive.com/<指纹>.asc`。HTTP 204 表示没有证书；兼容官方的旧 HTTP 404。HTTP 200 必须是 `PUBLIC KEY BLOCK` armor 中恰好一个目标主钥自签的 key-revocation 包：有效撤销、伪造、错钥、畸形或未来证书均停止下载。网络故障不能视为未撤销。不会跟随重定向，也不带账号凭据或 Cookie。取消和超时保留各自错误码。

账号授权资源各自申请 grant：仓库根的 `_keys/public.gpg`、`repository.json`、`repository.json.asc`，固定版本下的 `complete/manifest`、`complete/manifest.asc`，以及 ZIP。保留两项 LRU 和 TTL 边界，不能复用 manifest 的授权访问签名或 ZIP。主进程只接受这三个固定根资源及合法 complete 资源；没有任意 URL IPC。grant、签名 URL、账号凭据和可复用授权不写入下载日志、安装记录或界面状态。

签名通过后，仓库格式必须为 `0.3`，包含请求的固定 revision，且 `completeSize` 与 manifest 中 ZIP 大小相同。解析使用独立字节快照。内容 API 提供的模组/版本定位信息与签名元数据分开处理；验签层不改写原始签名字节或用户预设，安装器继续使用原事务边界。

## 已安装文件的信任来源

本次官方 HOI4 complete manifest 只有 ZIP 本体的大小与整文件 SHA-256，不含 ZIP 内部逐文件摘要。0.16 的安装器从完成信任链、ZIP 大小与摘要校验的提取结果生成本地索引，`descriptor.mod` 先按安装规则清理再取摘要。索引绑定 modId、revision、archiveSha256，位于固定控制根 `indexes/<uuid>.json`；安装记录用独立 SHA-256 和长度引用索引，内容迁移不移动控制根。

校验不把现有安装的当前内容自签成基准。没有可用索引的旧安装须重新下载并验证同版 ZIP 后比较；健康时只补索引，保留 installationId、路径和预设。损坏时在新目录构造同版内容，事务替换注册并保留旧内容及实际旧注册文件；注册文件已改写或丢失时也按捕获状态支持回滚，危险链接则拒绝。公开身份的健康检查完全本地；账号身份先核对会话，文件完整时不请求内容元数据、签名资源或 ZIP。需要下载、暂停后恢复时，继续执行本节完整信任链、撤销、访问权限和账号绑定检查。细节与限额见 [安装验证与修复](pdx-repair.md)。

## 验证与分发

真实公开小资源和固定生产根的原始字节已在系统 Node 中完成密码学验算，夹具及 SHA-256 来源见 `tests/fixtures/pdx-signatures/README.md`；未下载该真实模组的 ZIP。负向测试覆盖内容篡改、错钥、无根认证、弱摘要、日期/权限/绑定/背签、撤销、额外包和输入上限。

私有下载整合使用运行时生成的独立测试根与仓库钥、真实账号服务/内容服务/安装器以及小 ZIP。覆盖六个资源的独立授权、安装、暂停重开、重新验签后 Range 续传和账号变化；签名在暂停后被修改时，不请求剩余 ZIP，也不安装已有片段。旧传输单测和历史 UI 流程可显式替换密码学边界以聚焦传输行为；新增默认公开验证、私有实签整合和签名 UI 流程独立验证真实验证器，不以替身作为密码学证据。

0.16 的 `node scripts/test-pdx-resume-ui.mjs --repair` 使用真实验证器和隔离签名链完成健康时不取内容资源、同版修复、旧用户文件和预设保留，累计十八次资源授权与六次撤销查询。本地索引与安装事务的独立检查范围见 [修复文档](pdx-repair.md)；完整测试数及本版制品核对以 Roadmap 为准。

第三方完整 LGPL/GPL 文本、对应源码与独立模块替换材料见 [OpenPGP 分发说明](third-party-openpgp.md)。库随包独立解包，静态制品核对运行时文件、独立 CJS 解析、固定根指纹和许可材料。当前结果以 [Roadmap](../ROADMAP.md) 及本版本归档为准。

未执行 Electron、便携程序、CPatch、真实游戏、Steam SDK 或真实账号操作。Node 与无界面浏览器验证不替代这些运行验收；Roadmap 仍包含单文件网络修复、增量、官方 files/内部缓存兼容等工作。
