# 游戏统计 · 0.27.0

侧栏新增“游戏统计”。每次从本启动器成功启动游戏后建立独立记录，持续到该游戏进程退出，保存历史、资源占用趋势以及当次游戏版本、版本实例、播放集名称和启用模组数。不同存档、同一存档的多次游玩分别记录，不推测存档身份或合并战役。

## 使用

自动记录默认开启，可在统计页通过“自动记录后续游戏”开关关闭。开关只影响以后启动的游戏，当前记录继续到游戏退出。已经在运行的游戏不会追溯补记；从 Steam 或其他程序直接启动的游戏不自动加入记录。

统计页每五秒刷新，显示运行时长、平均／峰值 CPU 使用率、平均／峰值物理内存与采样次数。两张趋势图展示 CPU、物理内存和私有提交内存，鼠标移到曲线上可查看对应采样点。下拉框可查看最近 100 次游玩；历史文件保存在本机，不自动删除。

关闭启动器或开启“启动游戏后关闭启动器”，独立采集器仍会运行。游戏退出后采集器自动保存结束状态并退出；重新打开启动器可查看结果。采集器启动或记录失败只影响统计，不把已成功启动的游戏误报为启动失败，也不回滚游戏正在使用的加载配置。

## 两次游玩比较与备注

0.27.0 可分别选择 A 与 B 记录。曲线按启动后的经过时间叠加，摘要表展示 A、B 与 B−A；CPU 差值用百分点，内存用 GiB。较短记录时间范围外显示无采样，缺测仍保留断点。游玩阶段、硬件和其他程序会影响占用；这些差异不能代表游戏日期推进速度。

每条新记录保存实际启动时的游戏版本、启用 Mod 顺序与版本引用、有效 DLC 及游戏设置，比较时列出配置变化。普通启动不会额外计算整套 Mod 文件摘要，因此内容标为尚未核实；同版本内容变化需通过战役检查或组合快照核验。旧记录或损坏环境显示无法比较配置，资源指标仍可读取。

A 记录可编辑最多 4000 字符的游玩备注，B 记录显示其已保存备注。备注与环境使用独立文件，不会被后台采集器的摘要更新覆盖；当前记录轮询不会覆盖尚未保存的草稿。

## 指标边界

- CPU 使用率来自目标进程累计 CPU 时间的差值，按有效经过时间及整机逻辑处理器数归一为 0–100%。例如 16 个逻辑处理器中使用一个处理器的全部算力，约为整机 6.25%。CPU 峰值是采样窗口峰值，不是逐帧或瞬时峰值；首点没有差值时显示缺测。
- 物理内存是进程驻留工作集，私有提交内存是进程私有提交量，两者不相加，也不代表整机内存占用。物理峰值结合系统的进程生命周期峰值；其他峰值来自有效采样。平均值按有效时间计算，内存采用相邻有效点之间的梯形积分。
- 缺测保留为 `null`，不填成零；记录中断、暂未更新、采集不可用与游戏正常结束分别显示。记录或系统故障时不补造缺失区间。
- 长记录会逐步合并趋势点，后台仍每五秒维护摘要；界面最多读取 1200 个显示点。含缺测的合并组保留断点，可能扩大图上缺口的时间范围。整段记录的摘要与峰值保留，压缩后的趋势用于观察变化，不代表逐秒原始数据。
- 这一版不采集 FPS、帧时间、卡顿、显卡占用或游戏日期推进速度。现有 HOI4 日志不足以连续测量“一天耗时”，这些指标不会用 CPU 或刷新率推算。

## 采集与存储

Windows x64 使用本项目的小型 .NET Framework 采集器，读取指定游戏进程的系统计数。它不依赖启动器窗口或账号连接。采集目标来自成功启动游戏时的可信 PID、可执行文件及进程创建时间绑定，渲染器不能提交采集路径或任意 PID。

采集器随便携包提供；启动前校验并放入统计目录下按内容 SHA-256 命名的持久缓存，再从那里运行，保证便携启动器退出、解压临时目录清理后仍可采集。每个采集器只服务一条会话，游戏退出后自行结束。

记录位于 Windows 应用数据目录的 `IRONCLAD/game-performance/`：

- `settings.json`：自动记录开关，与游戏语言、播放集和版本实例配置分开保存。
- `index.json`：最近 100 条记录的索引；未列入索引的旧会话目录保留。
- `sessions/<UUID>/session.json`：受控采集配置及启动时上下文。
- 同目录 `summary.json`、`samples.jsonl`：原子更新的摘要与持续落盘、有界压缩的趋势；`monitor.lock` 防止重复采集器覆盖正在记录的结果。
- 同目录 `environment.json`：可选完整启动配置，严格校验且绑定会话 ID；`annotation.json`：独立游玩备注，保存时保留前一份字节。缺失或损坏的 sidecar 不阻断指标读取，原件保留并提示。
- `monitors/<SHA-256>.exe`：与随包采集器逐字节一致的持久副本，已有缓存被改动或重定向时拒绝执行。
- `corrupt-backups/<原文件名>.<SHA-256>.bak`：损坏的索引或统计设置在下一次写入替换前，按原始字节备份并校验；备份失败时保留原件、停止替换。备份不自动删除。

统计 IPC 暴露 `getGamePerformance()`、`getGamePerformanceSession(id)`、`setGamePerformanceEnabled(boolean)`、`setGamePerformanceNotes(id,notes)` 和 `compareGamePerformance(beforeId,afterId)`。读取有文件类型、路径、体积、结构、状态及数值校验；损坏文件保留并提示。高频统计读取与比较不写入诊断事件，备注原文不进入日志。

## 开发和验证

`npm run build` 先通过 Windows 自带的 .NET Framework x64 C# 编译器构建独立采集器，再构建界面；不下载外部工具。`npm run build:performance-monitor` 可单独构建。原生源文件为 `scripts/native/game-performance-monitor.cs`，构建脚本为 `scripts/build-performance-monitor.cjs`。采集器和对应源码均随便携版提供。

后台测试使用确定性采样以及隔离的普通 Node 进程，覆盖 CPU／内存计算、缺测、长记录压缩、真实目标退出、创建时间／镜像不匹配、重复采集器、链接与损坏数据、设置保存和独立父进程退出后的采集。测试不会启动、停止或修改真实游戏。

0.26.0 后台专项 30 项、Node 全量串行 1393 项通过。两次默认并行全量分别在旧实例／目录测试的临时目录清理时出现 `ENOTEMPTY`，没有功能断言失败；原始日志保留，实例专项单独 10 项和最终串行全量均通过。

新界面专项 28 项、常规界面 54 项通过，覆盖趋势、采样点查看、历史切换与异步返回竞争、开关、空数据、缺测、不支持系统、读取失败恢复、示例标记以及中英文／1000px 布局。构建、全量测试、生产 preload 的隐藏桌面检查和便携包校验结果见 [0.26.0 验证汇总](../test-results/0.26.0/verification-summary.json)。

隐藏 Electron 检查已通过生产 preload 的统计读取、空历史与记录开关往返，并检查渲染后的启用状态和统计导航。便携包的 89 个业务／界面／资源文件、独立 x64 采集器与对应源码均核对一致；未启动便携程序或真实游戏做采集验收。

0.27.0 新增环境／备注专项 23 项，与原 30 项后台检查一起通过；18 项双次比较界面检查和 28 项原统计界面回归通过，包含缺测、短记录范围、旧环境、A/B 切换、未保存草稿和重开。最终全量 1549 项、生产沙箱五项工作流 11 项及制品证据见 [本轮汇总](five-improvements.md)。
