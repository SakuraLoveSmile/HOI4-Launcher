# Paradox 受管安装：验证并修复 · 0.20.0

IRONCLAD可以检查自己管理的PDX模组安装，并在原固定revision上修复。已有可信索引且文件完整时，公开身份只做本地检查、不联网；账号身份先核对登录会话，但不请求内容资源或ZIP。两者都不改变安装ID或预设。需要可信ZIP时先取官方files；实际内容404且可信仓库声明 `-1` 时独立验签并使用安装补丁，未声明时保留同版complete兼容。0.20允许该安装补丁的p以空源重建，最终仍必须产生与目标complete一致的单个完整ZIP；[通用清单/计划底座](pdx-patch-planning.md)尚未接通任意多目标修复，不提供单个解压文件的网络修复或官方内部缓存/断点兼容。

## 校验基准与存储

新安装先通过官方 OpenPGP 信任链、原始 repository/manifest 分离签名以及 ZIP 大小和 SHA-256 校验，再提取文件。安装器清理 `descriptor.mod` 中的 `path`、`archive`、`remote_file_id`，随后为实际安装字节建立逐文件大小和 SHA-256 索引；校验不会要求清理后的描述文件等于原 ZIP 字节。

`electron/pdx-file-integrity.cjs` 只接受已提取、身份和摘要匹配的可信源文件，生成以下本地应用状态：

```text
<安装器控制根>/indexes/<uuid>.json
```

索引绑定 `modId`、`revision`、`archiveSha256`，条目为相对路径、字节数和 SHA-256。安装记录保存独立引用 `{version:1,id,sha256,bytes}`；读取时先校验索引自身的长度和 SHA-256，再校验绑定与条目。它是已验证 ZIP 派生的本地基准，不是官方签署的解压文件 manifest，也不防止有权同时改写安装数据库与索引的本机程序。

索引位于固定控制根；迁移只改变受管内容根，不搬动索引或控制数据库。版本记录的索引引用随记录保留。索引创建后若安装取消或失败，尚未被记录引用的索引文件可能保留；目前没有索引垃圾回收。

## 检查结果与限制

检查状态为 `intact`、`damaged` 或 `unverified`。有可信索引时扫描受管内容，按内容摘要识别同大小改写，并计数 `missingFiles`、`changedFiles`、`extraFiles`、`unsafeFiles`。`registrationIntact` 单独检查注册描述文件；其改变或丢失会阻止返回完整状态。

路径穿越、Windows 别名和大小写冲突不被接受。扫描不跟随符号链接或目录联接；文件硬链接、身份替换、危险路径和校验中的外部变化按不安全或失败处理。额外普通文件会计数并触发修复；空目录本身不计为额外文件。原安装中的用户修改不会由检查流程删除。

| 限制                   | 上限    |
| ---------------------- | ------- |
| 索引条目与扫描条目预算 | 100,000 |
| 预期文件总大小         | 20 GiB  |
| 单个预期文件           | 4 GiB   |
| 索引大小               | 64 MiB  |
| 返回的逐项问题         | 100 条  |

问题列表超限时保留总计数并设置 `issuesTruncated`。检查前后核对文件、目录及父目录身份和时间戳；不能把大小、CRC 或 mtime 单独当作内容摘要。文件校验模块对缺少索引、索引文件缺失、引用或索引校验失败返回 `unverified` 及 `baselineReason`；安装数据库本身含畸形引用时仍由数据库校验拒绝加载。两者都不会把当前磁盘内容直接登记成可信预期值。超过限制会停止并保留现有内容。

## 服务与桌面边界

主进程安装服务增加：

```js
installer.verify(modId, {
  userDataPath,
  installationId,
  signal,
  onProgress,
});
installer.list({ includeDamaged: true });
```

公开安装记录包含 `installationId`，对应当前事务 ID。默认 `list()` 只返回内容根身份与注册描述文件匹配的安装，并不逐文件扫描；`includeDamaged:true` 还返回已登记但内容根或注册文件改变、丢失的记录，带 `installationDamaged:true`。逐文件是否完整以 `verify` 结果为准。校验与安装共用原队列、磁盘锁、运行游戏检查和用户目录保护。

下载协调器提供 `repair({modId,authorization?:"anonymous"|"account"})`。具名 IPC 为 `pdx:repair`，preload 为 `repairPdxMod(input)`。渲染层只能传模组 ID 和下载身份，不能传路径、revision、installationId、账号 ID、令牌或下载 URL。

服务从当前游戏用户目录查找受管安装，固定其 revision 和 installationId。下载计划必须继续匹配该版本和既有归档摘要；从解析计划到安装提交，原安装发生变化时停止。此操作不会静默升级到 latest，也不对任意本地目录、Steam 内容或 HOI4 本体承诺 PDX 修复。

## 健康、旧安装与损坏安装

1. 已有可信索引且本地检查完整：直接成功。公开身份不联网；账号身份先通过 `bindSession` 核对登录会话，可能请求 `/accountdetails`，但不请求内容元数据、签名资源或 ZIP。不改变 installationId、注册文件和预设。
2. 旧安装没有可用基准：重新取得并验证同一固定 revision 的完整 ZIP，可以是 files/complete 直接下载或有声明的安装补丁重建，再提取和清理描述文件后与原安装比较。若原内容和注册文件均完整，只补建可信索引，保留原目录和 installationId；不能把旧安装当前摘要当作预期摘要。
3. 内容或注册文件损坏：以同版可信 ZIP 构造新的完整目录，复用原安装事务切换注册和数据库。成功后 installationId 改变，注册文件名与固定 revision 保持一致，预设成员和顺序不变。

修复保留旧内容目录及其中的用户修改；存在的普通注册文件按修复前实际字节备份，即使它已经改写。原注册文件丢失时允许重建，不伪造旧备份。提交失败时按捕获的原状态回滚，支持恢复已修改的注册内容以及原本不存在的注册文件。不安全、含不明硬链接或无法稳定备份的注册文件会被拒绝；提交时又被外部改动的文件不会被覆盖。

旧注册备份与旧内容通过结果中的保留路径展示。无法按原受管描述验证的历史内容在后续迁移中保留原处并报告为保留路径；修复不授予迁移器删除这些内容的权限。事务恢复不确定时保留 journal 并要求显式恢复，不能报告健康或继续破坏性操作。

## 进度、暂停与恢复

`verifying` 阶段占用操作门，可取消，不可暂停；取消不会删除或修改原安装。需要传输时，完整 ZIP 或已选安装补丁使用既有限速、断点、暂停与手动恢复机制。目标 `plan` 与补丁 `transferPlan` 分开，checkpoint 绑定实际传输包，不能把补丁前缀用于 complete。重开不自动联网或重放任务；日志保留 repair 操作、固定 revision 和 installationId，手动恢复重新校验原安装，再重新获取签名资源、验证撤销状态、检查当前访问权限和账号会话，继续精确匹配的计划。已选补丁变化或失效时保留片段并停止；补丁应用和安装不可暂停。

补丁仍只生成一个目标ZIP，允许同一目标最多一个d和一个n/p/k。空operations或仅d只有在可信旧ZIP与目标大小/摘要一致时才能隐式复制；安装补丁的p没有旧源时使用0字节空源，不能借用损坏安装目录充当源。d只表示新空工作区目标的逻辑阶段，不删除旧安装、缓存或玩家文件。c/s、多个producer、其他目标或额外payload拒绝。

补丁持有可信complete能力并独立验签，容器与payload验证完成后在安全工作区生成 `content.zip`，目标长度、累计摘要和fsync后落盘重读摘要均匹配complete才安装。工作区产生固定文件的身份/摘要证明；协调器持久化后，清理器独立复核再删除已知暂存文件，未知、取消/崩溃遗留或外部改动内容保留。已选补丁的授权、签名、容器、源、目标或网络错误均停止，不静默改取complete。通用manifest和六操作计划只解析/核对元数据，不改变这些实际执行和事务权限。

账号模式绑定当前登录会话；退出、同账号重登或会话失效会中止可取消阶段，普通 token 续期保留绑定。最终提交使用原事务的不可取消边界：完成最后的取消、游戏、用户目录与暂存验证，并在 journal 写入后再次检查取消；随后注册与数据库提交作为事务完成或恢复。下载层以安装事务的最终结果判断是否成功。完整机制见 [断点恢复](pdx-resume.md) 与 [签名验证](pdx-signatures.md)。

## 协议依据与验证范围

本机官方 CPatch 的只读研究确认，本次 HOI4 complete manifest 只有一个 ZIP 条目，包含该 ZIP 的整文件 SHA-256，没有内部逐文件摘要。官方修复先尝试仓库根的 `files/<Size>_<Hash>`，404 后回退固定版本的 `-1_to_` 安装补丁；该单 ZIP 布局中的 manifest 修复单位仍是整个 ZIP。1,024 字节 SHA-256 读取缓冲不是分块完整性协议。更详细的静态证据见 [CPatch 研究](cpatch-signature-research.md)。

0.17 依据补核的 Base64URL 编码、路径和授权证据扩展了精确 files 路由，当时 files 404 后仅回退 complete；0.18 增加缓存保存和独立内核，尚未接通补丁。实际匿名 HEAD 的 files 404 和 complete 200，以及已验签的小型补丁资料见 [内容下载路径](cpatch-download-paths.md)。0.19 只有 files 实际内容 404 且可信仓库声明 `-1` 才转安装补丁，无声明时继续 complete 兼容。各来源独立授权并受同一目标摘要约束；权限、会话、签名、大小、摘要、重定向或网络错误均停止。

0.16 历史结果：系统 Node 最终全套 876/876 通过，失败/取消/跳过为 0。安装/迁移/下载/真实签名修复集中组 112/112、下载协调器 33/33 通过；独立文件校验模块 34 项已由最终全套覆盖，新增真实签名修复整合 7 项同时纳入集中组和全套，以上数字不相加。检查覆盖同版修复和旧版可信基准补建、修改/缺失注册恢复与回滚、固定 revision/installationId、用户文件与预设保留、参数拒绝、暂停重开、账号失效及续传重新验签。

0.16 的无界面 Edge 常规 54 项及修复流程通过，后者累计 18 次资源授权和 6 次撤销查询，证据保留。0.17 全套 894/894 通过；当前 `--repair` 使用真实业务和签名验证器，仍覆盖简中/英/德、1000px、健康无内容请求、同版修复和旧文件/预设保留，累计 19 次资源授权和 6 次撤销查询，多出一次 files 404 授权。真实签名集成另覆盖 files 直接下载与 files/complete 两种来源的 Range 续传。健康账号先核会话，不据此声称完全离线。完整结果和制品证据见 [Roadmap](../ROADMAP.md)。

0.19系统Node1138/1138、常规54项无界面UI和签名补丁更新/续传/安装修复流程属于历史结果。交付后补验两组真实官方大型p差分，见 [实际字节验收](official-patch-acceptance.md)；另有真实 `-1_to_3` 安装补丁实际执行n并匹配可信complete，随后生产安装器在项目隔离目录安装。8,155个普通文件及注册在提交后和服务重建后两次完整检查均为intact，原ZIP不变，见 [安装补丁与隔离安装](official-install-acceptance.md)。这没有验收真实修复协调器、账号或玩家目录中的服务全链，也没有执行CPatch/xdelta3、模拟中断事务或进程重启。
