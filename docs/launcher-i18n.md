# 启动器界面语言 · 0.15.0

设置页的「启动器语言 / Launcher language」提供 English、Deutsch、Español、Français、日本語、한국어、Polski、Português、Русский、Türkçe、简体中文和繁體中文，共十二种界面语言。保存成功后切换界面，重开后继续使用；写入失败时保留当前语言和文件。旧版 v1/v2 设置缺少语言字段时默认简体中文，沿用 schemaVersion 2。

## 数据边界

设置字段为 `launcherPreferences.language`，与 `gameOptions.language` 分开。保存偏好时展开并保留完整 `launcherPreferences`（包含 `closeOnLaunch` 及可选 `homeLayout`），不改预设、DLC、描述文件或游戏配置。

`src/i18n-core.mjs` 提供字典和一次性占位符插值；`src/i18n.jsx` 管理界面、日期、文档语言及富文本。React 节点作为占位值保留，不拼接 HTML。字典使用无原型对象和自有属性检查，未知键原样显示。

`src/language-info.json` 是渲染层和主进程共享的可用语言名单与地区代码。所有独立词典均覆盖 0.16 当前 1,486 个唯一消息键，并和英文键集合及占位符次数逐项核对；不以英语填充缺项。0.15 的历史基线为 1,456 键，当时增加签名无效、撤销状态无法核对、签署密钥已撤销三项下载诊断。0.16 再增加 30 键，覆盖验证/修复操作、文件结果计数、可信基准缺失、完整包下载提示、注册文件及安装变化、保留路径和安全限额等界面与诊断。词典随包提供，不调用翻译服务。各语言生成独立构建分块；语言之间复用同一套页面及诊断边界。繁体中文、日语和韩语界面分别使用 Windows 的正体中文、日语和韩语字体回退；葡萄牙语采用 `pt-BR` 地区格式。

程序标签、按钮、状态和明确的应用诊断在显示边界翻译。模组/预设名称、作者文字、路径、远端新闻/描述、账号及硬件名称直接显示；即使内容恰好叫「设置」「总览」也保持原样。新 Paradox 下载/订阅的生成标题带 `titleIsFallback` 标志，只有该标志明确存在才翻译；真实同名标题及旧记录保留原文。

旧字符串诊断继续使用完整句模板匹配，动态值原样代入，不递归翻译。0.14 新增显式结构化诊断：应用拥有的模板节点可以嵌套，字符串和数字值始终为字面量。新闻/目录缓存回退、严格游戏设置解析及底层 PDS 原因、模组创建/编辑回滚和保留路径、目录迁移失败与恢复失败、Paradox 发布待确认及网络/清理原因使用此格式。未知底层和远端错误即使恰好等于应用消息键也保持原文，不根据文本推断来源。

`electron/diagnostic-message.cjs` 生成和规范化元数据，旧 `Error.message` 和状态 `error` 字符串保留。节点为 `message`（已知 `key` 与 `values`）、`sequence`（`parts`）或 `literal`（`text`），均有 `kind` 字段。仅接受英文词典的自有键；限制为深度 8、128 个节点、8192 个输入字符、每数组 64 项。无效或超限时丢弃元数据并显示旧消息，不改成新的内部错误。迁移状态仍遵守原有 2000 字符上限；超长错误使用同一截断后的字面量。附加错误属性不会进入格式。

Electron IPC 会丢弃自定义 Error 属性，因此主进程只为通过规范化的诊断返回内部错误信封，preload 将其恢复为带诊断的 rejected Error；具名方法的调用约定不变。新闻/目录/迁移/发布状态则在原 `error` 旁增加可选 `errorDiagnostic`，新闻和目录缓存格式不变。`formatDiagnostic` 在 UI 再次验证边界，toast 和相关面板优先显示结构化信息，失败时保留旧字符串。发布历史可保存可选元数据，旧记录无需迁移；日志与导出保留原诊断文字。

以动态值开头的通用组合/后缀模板，只有在原始前缀是已知程序标签或具有固定开头的程序诊断时才匹配。裸「已{0}」不参与诊断推断，Steam 三种成功状态使用完整固定句。未知文本仅包含「，但」或「失败」不会触发这些通用模板；识别前缀不递归翻译其内容。

`electron/native-i18n.cjs` 仅对主进程显式提供的原生标题、关闭确认消息/按钮和 JSON 筛选名称精确查表。首次 renderer 读取状态以及成功保存设置后更新缓存，无额外模组扫描。文件路径、选择结果、导入/导出 JSON 和诊断报告不翻译；诊断默认导出 ZIP，JSON 仍可选，`ZIP` 是通用格式名称。文件选择器内部的系统按钮等由 Windows 决定语言。

## 官方语言范围

官方目标为 `en`、`de`、`es`、`fr`、`ja`、`ko`、`pl`、`pt`、`ru`、`tr`、`zh-hans`、`zh-hant`。后端验证这些代码；0.11 的选择器覆盖全部十二种。先前已保存的其余有效代码在升级后直接使用对应词典，无需再次保存；未知代码的显示层仍回退英语，保存时拒绝未知代码。游戏语言选项与界面本地化独立。

## 验证

Node 测试覆盖语言迁移/严格字段校验、游戏语言与内容不变、完整键集合、重复键、字典占位符、界面字面量覆盖、原型名称回退、路径和用户值原样代入。新增容量与数量限制检查允许当地千位分隔符，但要求数值相同。逐项比较渲染层和原生标签，防止语言名单或词典顺序分歧。主进程 mock 验证文件对话框、各类忙碌状态关闭确认、待保存/保存失败不提前切换以及数据不变。

`npm run test:i18n-ui` 使用真实设置服务、隔离模组/游戏夹具和无界面 Edge。逐语言检查切换、后端/页面重开持久化、失败保存、中文用户内容和远端新闻保留、生成标题、地区日期/文档语言及 1000×740 最小窗口。各语言均检查设置、总览、模组详情、Paradox 与 Steam 面板，并检查 740、820、821、900、1050 像素高度；侧栏装饰区按剩余空间隐藏，保留导航及底部状态。所有非本机浏览器请求被阻止；杀毒软件注入脚本单独记录。截图和最终结果归档在 `test-results/0.11.0/`；0.10.0 及更早证据保留在各版本目录。

新版 Electron 原生运行时和真实游戏/账户/SDK 尚未验收。系统 Node mock 和后台浏览器验证不能代替这些验收。

0.14 的 `npm run test:diagnostics-ui` 使用真实 preload 源码与隔离具名 IPC 响应，在无界面 Edge 中检查英语、德语、日语各五类复合诊断，共 15 组；通过实际 UI 操作触发设置/模组错误并验证 rejected Error 未被当作成功。路径、模组名称、远端原文与含 `{1}` 的字面量保持原样，应用外部请求为 0。节点树的核心格式化另覆盖全部十二种可选语言；这些结果保留在 `test-results/0.14.0/`，旧 0.11/0.13 的额外流程也作为历史证据保留。

0.15 完整 Node 821/821（包括该版十二语言键集合及占位符检查）和常规无界面 UI 54 项通过，该版签名下载暂停/重开/续传流程另使用真实验证器通过，作为历史证据保留。0.16 的修复操作沿用相同的字面量、路径与远端原文边界；真实业务 `--repair` 无界面流程已覆盖修复对话框、结果和最小窗口。当前完整结果与分发证据见 [ROADMAP.md](../ROADMAP.md)，功能与协议边界见 [安装验证与修复](pdx-repair.md)。
