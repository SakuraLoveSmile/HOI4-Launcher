# IRONCLAD backend / desktop contract · 0.28.0

0.28.0 adds `update:state/check/download/cancel/install/releases`, exposed only
through the named preload methods. Main owns the fixed GitHub repository, update
cache and portable executable path; renderer supplies no URLs, paths or PIDs.
Stable releases must be newer than the current version, with a matching portable
asset and SHA-256 metadata. Downloads verify exact size and digest; installation
rechecks the bytes and stages beside the portable executable before quit.
An installation reserves all mutation IPC, rejects existing work and a running
game, and exits only after the hidden helper successfully spawns. The helper
waits for exit, retains the original executable and attempts rollback on failure.
Development builds offer manual replacement. See [updates](docs/launcher-updates.md).

Mod context menus now route an installed source ID to the existing project
creation dialog. Creating the independent project still requires form submission,
with the baseline unknown by default. Source files and playset state are preserved.

0.27.0 adds campaign records, complete enabled-Mod content snapshots, coverage
evidence, performance comparisons and a compact home. Main owns all filesystem
paths. Renderer IPC accepts generated record/report/evidence IDs; campaign binding
uses a native picker constrained to the active instance's local `save games`.
Campaign environments capture game version, ordered enabled Mods, content digests,
DLC and effective game options. Binding creates a verified save backup. Continue
requires a fresh review token bound to record bytes, current configuration and a
ten-minute deadline. Save restoration preserves the current bytes before replacing;
configuration restoration creates a new playset. It does not restore Mod content.

`campaigns:state/progress/cancel/bind/update/review/review-current/accept/restore-config/backup/restore-backup/folder`
expose only their corresponding preload methods. Campaign data and backups live
under userData/campaigns. Reviews and copy operations are cancellable; updates use
exclusive installation, retained previous bytes and conflict detection.

`snapshots:state/progress/cancel/create/verify/restore/folder` store the actual
enabled content and external descriptors under userData/playset-snapshots/UUID.
Only a verified `snapshot.json` commit makes a snapshot complete. Disabled members
retain references only. Restoration verifies all bytes, creates independent local
projects with pinned revisions, journals progress, then atomically selects a new
playset. Source Mods, playsets and snapshots are preserved. Limits are 4 GiB per
file, 20 GiB/100000 entries per Mod, 100 GiB/200000 entries per snapshot. Copy and
verification can be cancelled; project creation and final commit cannot.

`coverage:scan/progress/cancel/evidence` scan trusted active directory/ZIP sources
with bounded file, text, archive and output budgets. Groups cover same-path,
replace-path, event-id and focus-id, with one-based playset order, source path,
line and optional declaration/affected role. Missing or unreadable sources yield
explicit partial results. Only the newest report can serve evidence, and config,
descriptors and file identity are rechecked before returning escaped excerpts.
Results establish possible overlaps, not load winners, prerequisites or compatibility.
File work and launch/config changes share the existing main-process exclusion gate.

Performance sessions now have optional validated `environment.json` and independent
`annotation.json` sidecars. Environment capture uses effective launch settings and
DLC, leaving Mod content unverified during ordinary launch. Capture failure does
not prevent launch. `setGamePerformanceNotes(id,notes)` and
`compareGamePerformance(beforeId,afterId)` use performance:notes/compare; notes are
limited to 4000 characters and never logged. Comparison returns validated context
differences or an explicit unavailable result for legacy/missing context. Read
state stays lightweight; collectors never rewrite either sidecar. Charts align
elapsed time, preserve gaps and show summary B minus A without inferring simulation
speed. See [five improvements](docs/five-improvements.md).

Optional global `launcherPreferences.homeLayout` accepts `full|compact`; absence
retains the existing full home without rewriting old settings on read. Every
preference update preserves the other fields. Compact home fetches campaign and
recent-session metadata independently, handles stale responses and read failures,
and routes continue through the same full review. Its configuration summary does
not hash actual Mod files. UI layout/language/close preferences are excluded from
game environment comparisons.

0.26.0 adds game performance records. A successful launch returns a compact
`performanceContext` snapshot of game version, instance, playset, enabled mod count
and launch mode. Main starts statistics only after launch has committed, treating
all collector failures separately from game launch. No renderer can submit a PID
or executable path. A detached, hidden Windows x64 .NET collector samples only the
launched process every five seconds and finishes when that process exits. It runs
from a verified persistent copy so portable extraction cleanup and closing the
launcher do not stop collection. Process executable and creation time bind identity.

`createGamePerformanceService({storageDirectory,monitorPath})` exposes main-only
`startSession(input)`, plus `getState()`, `getSession(id)`, `setEnabled(boolean)`.
Renderer methods `getGamePerformance`, `getGamePerformanceSession`, and
`setGamePerformanceEnabled` use protected performance:state/session/enabled IPC.
Read IPC does not generate diagnostic events. The global preference defaults on,
affects future launches only, and lives under userData/game-performance separately
from instance settings. Histories capture immutable launch context; the latest 100
are indexed without deleting older directories. Trend sampling is bounded and
progressively compacted; displayed details contain at most 1200 points, retaining
full-session aggregate peaks. CPU is normalized across all logical processors and
averaged over valid time; working set and private committed bytes are distinct.
Missing metrics remain null. Completed, interrupted, unavailable, stale and active
states are distinct. FPS, GPU and simulation date progress are not measured.
Compaction conservatively retains per-metric nulls; summaries remain independent.
Before replacing corrupt index/settings files, their exact bytes are durably
backed up and verified under corrupt-backups; backup failure prevents replacement.
See [game performance](docs/game-performance.md) for lifecycle, storage and checks.

0.25.2 preserves descriptor `dependencies` as author-declared load order or
compatibility references. Names alone do not prove required prerequisites; state
retains the legacy `missingDependencies` field as an empty array. Overview, library,
playset and detail views no longer show missing-dependency warnings from these
strings. Details label them as load order references and direct users to the
author's instructions for requirements. No remote dependency discovery, automatic
enabling, descriptor rewrite or launch-order change is introduced. Missing enabled
members and unavailable pinned revisions retain their existing launch guards.
See [dependency warning fix](docs/mod-load-order.md).

0.25.1 resolves cover MIME from validated image bytes, including image-extension
mismatches. Missing pictures use bounded conventional root thumbnail candidates;
extensionless safe paths also try supported suffixes. Explicit sources retain
precedence in directories and ZIPs. Scanned presentation state may expose a resolved
picture candidate without rewriting source metadata. Cover-only PNG/JPEG parsing
discards data after the validated end marker before forwarding bytes; the shared
validatedRaster API retains strict trailing-data rejection. Static WebP supports
bounded C2PA metadata. Explicit Workshop install refresh retries failed cover URLs;
ordinary state polling does not. See [cover behavior](docs/mod-thumbnails.md) and
test-results/0.25.1/verification-summary.json for verification and local audit.

Mod context-menu behavior is defined in [mod context menu](docs/mod-context-menu.md).
Both playset columns expose the same nine actions, guarded by current source,
membership, capability, busy and running-game state. Settings add per-instance
`modDisplayNames: {[modId]: {name,kind:"custom"|"translated"}}`, with trimmed
1–128-character names and at most 10000 entries. Legacy settings receive an empty
map. State mods expose `originalName`, `displayNameKind`, `canDeleteLocal` and
`canDelete`; `name` is the presentation alias when present. Dependency matching,
launch and playset exchange retain source metadata rather than the alias.

Version instances are defined in [version isolation](docs/game-instances.md).
Settings normalize to schema 3 with `gameInstances` and
`activeGameInstanceId`. Existing top-level gameDirectory/launchMode/playsets/
activePlaysetId/disabledDlcIds/gameOptions/modDisplayNames remain the active projection, synchronized
to its instance on every save. launcherPreferences remain global. Legacy schemas
are migrated in memory to the non-isolated `default` instance without rewriting on
read. Instance changes are atomic and preflight the candidate state before saving.
The settings excerpt below documents the retained active projection; instance
records also persist their full profile snapshots in the schema-3 document.

The service adds createGameInstance({name,gameDirectory}), switchGameInstance(id),
renameGameInstance({id,name}) and removeGameInstance(id), each returning State.
The preload exposes the same methods except createGameInstance accepts only {name};
main selects its gameDirectory via native dialog and cancellation returns null.
Named IPC channels are instances:create/switch/rename/remove. Ordinary saveSettings
rejects gameInstances/activeGameInstanceId patches. All instance IPC reserves the
existing directory-change gate and rejects a running/starting game, active file
operations or recovery. Profiles are limited to 50 including the undeletable default;
names are trimmed 1–128 characters, identities are UUIDs.

New instances start with empty playsets and their user directory is derived only in
main service from settingsPath's parent/game-instances/<id>/user-data. All scanning,
authoring, loadouts, options, saves, cache and installed PDX registrations use this
directory. Launch adds one `-userdir=<absolute forward-slash path>` argument for
isolated instances, rejecting conflicting metadata arguments before game-file
writes. The default retains userdir.txt behavior. Removal only drops the record and
switches an active removed instance back to default; its files remain. A paused PDX
download resumed under another instance throws USER_DATA_CHANGED without modifying
its checkpoint/status/journal; switching back allows resume.

Local Mod projects, selective upstream merging, project history/backup and fixed
project versions are defined in [Roadmap 2 contract](docs/roadmap-2-contract.md).
The project service owns local identity and immutable snapshots; upstream adapters
capture independent candidates. Desktop paths come from native dialogs or verified
sources. Launcher source guards use the internal getSourceState scan to avoid
project-queue re-entry. These additions do not complete Roadmap 1 acceptance.

`createLauncherService({settingsPath,documentsPath,steamRoots?,spawnProcess?,processProbe?})` is exported by `electron/launcher-service.cjs`. Mutations serialize; injection seams never cross IPC. Game user directory resolves official metadata and userdir.txt.

## Settings and state

```js
{schemaVersion:3,gameDirectory:"",launchMode:"normal",activePlaysetId:"default",
 playsets:[{id:"default",name:"默认预设",modIds:[],modOrder:[],
   disabledDlcIds:null,modReferences:[],origin:null,unmappedDlcIds:[]}],
 disabledDlcIds:null,gameOptions:{},modDisplayNames:{},
 launcherPreferences:{closeOnLaunch:false,language:"zh-hans"}}
```

modOrder retains disabled members; modIds is its enabled ordered subset. References are {id,name,source,remoteId,version?}; source is local/workshop/pdx. Null DLC selection inherits existing game state; [] enables installed DLC. Unknown DLC and unavailable required PDX revisions block launch. Names are 1–128 characters; retain at least one preset.

The 0.22 renderer exposes these existing playsets in a two-column workspace. Library membership uses modOrder, independently of enabled state. Search and library sorting never mutate member order; filtered member arrows and drag use full-list positions. Switching activePlaysetId refreshes scanned state to reflect the newly selected pinned Paradox revisions. Existing schema and IPC remain unchanged. See docs/playsets.md.

getState returns settings/game/mods/paths/warnings/launchBlockedReason/launchStatus/dlc/gameOptions/continueGame. Reads never launch or change game settings. Initial game detection can create IRONCLAD's own settings.

launcherPreferences is replaced as a complete nested object; spread existing fields when changing language, closeOnLaunch or homeLayout. Missing legacy language normalizes in memory to zh-hans without changing gameOptions.language or game files. Settings accept the official 12 codes: en/de/es/fr/ja/ko/pl/pt/ru/tr/zh-hans/zh-hant. UI catalogs in 0.11 cover all 12; previously saved valid codes now select their own catalogs. Unknown codes fall back to English for display but are still rejected by settings validation. src/language-info.json is shared by native and renderer labels and ships with all locale JSON. Each dictionary has the complete 1486-key baseline in 0.16, adding 30 keys to the historical 0.15 baseline of 1456. See docs/launcher-i18n.md.

## Service methods

- getState(), detectGame(), saveSettings(patch); save returns normalized settings.
- setModDisplayName({modId,name,kind}), resetModDisplayName(modId) → State. Named IPC is mods:display-name/reset-name. Only current scanned IDs can gain aliases; reset removes the active instance's mapping. Deletion retains aliases for later reinstall. No source descriptor is renamed.
- getLocalizedModName(modId) → {name:string|null} is desktop-only, routed to mods:localized-name. Existing CJK source names are reused; Workshop queries request Steam's schinese title, connecting explicitly if needed. Other sources or missing Chinese titles return null for manual input. The renderer always reviews an editable value before saving; no external translation service is used.
- updateMod(modId), deleteMod(modId) are desktop-only, routed to mods:update/delete. Main resolves the current scanned source and binds asynchronous operations to the active instance/user directory. Workshop update requests normal-priority download; PDX update uses the current playset pin and existing coordinator. Local/project updates are rejected. Workshop delete unsubscribes shared Steam content; PDX delete requires successful managed uninstall in this user directory and preserves recovery backups; independent local deletion uses the recycle transaction below. Successful removal clears modIds/modOrder/modReferences from all playsets in the current instance, retaining aliases. Unmanaged PDX, external/shared/unsafe local sources and projects reject deletion. Busy storage/publication/download/project/migration/recovery gates and game-running guards remain enforced; renderer paths are never accepted.
- getModThumbnail(modId) → null | {dataUrl,mime,width,height}; accepts only an ID registered by the current state scan, never a renderer path. Reads the descriptor's relative picture or bounded conventional thumbnail fallback from a verified local directory or ZIP without network or extraction. Missing, unsupported, changed and invalid sources return null. Matching source snapshots survive background scans; changed sources are re-registered on refresh. The main IPC is mods:thumbnail. See docs/mod-thumbnails.md.
- getLaunchStatus(), launchGame({resume?}); uses official arguments and adds --continuelastsave for resume. Validates current files before a backed-up transaction across options/loadout/generated descriptors. Process-creation failures roll back, later game crashes do not.
- getOfficialPlaysets(), importOfficialPlaysets(ids) → {state,importedCount,warnings}; consistent SQLite/WAL snapshot without original writes.
- importPlayset(text) → State; exportPlayset(id) → {document,omittedLocalMods}; official JSON ≤4 MiB, disabled/missing members/pins preserved, no automatic subscriptions.
- getCachePlan(), listCacheBackups(), clearCache(targetIds), restoreCacheBackup(id); fixed target plans, backup journals, running-game guard.
- createLocalMod(input), getLocalModMetadata(id), updateLocalModMetadata(id,input); mutations return {mod,state}. Fields name/folder/version/supportedVersion/tags/description; updates may be partial, folder cannot change. Main resolves IDs and rejects subscription-content edits.

## Other services

- mod-removal: canRemoveLocalMod({userData,mod,mods?,fileOps?}) → boolean; removeLocalMod({userData,mod,mods?,commit?,fileOps?}) → {backupDirectory}. Main-only inputs and injection seams never cross IPC. Only ordinary direct mod/\*.mod registrations and independent content inside the same mod directory are eligible; root/shared/external/project content, links, junctions and redirected ancestors fail closed. Actual removal scans all on-disk registrations and rechecks descriptor binding, file identities and ancestry. Content and registration move to userData/ironclad-mod-trash/<UUID>/ as content or archive.zip and registration.mod, with a synced schema-1 manifest of time, modId, userData and originalPath/backupName entries. The settings commit follows file moves; failure rolls back without replacing concurrent files, retaining recoverable content and reporting its path if incomplete. No automatic restore or recycle garbage collection is implemented.
- display-service: native display modes with hidden subprocess/timeout/cache.
- news-service: getNews({refresh?}) → {items,source,fetchedAt,error}; public official Steam announcements.
- mod-catalog: search({query,sort,page}) → {items,page,pageSize,totalCount,totalPages,source,fetchedAt,error}; 0-based pages of 12, query ≤120 characters, best/recent sorts. Cache keys contain all query conditions.
- account-service: login/getAccount/logout/cancelLogin return {status,account:{id,email,displayName}|null,remembered,canRemember,notice}. Password/digests/tokens never return to renderer. Only system-encrypted refresh tokens persist. Restricted authenticated request is main-process-only, with no IPC exposure.
- steam-workshop: injected client factory; only connect initializes App ID 394360. getState cannot initialize SDK. Once SDK/app/account validation succeeds, initial subscription read failures retain connected/account with a refresh warning; later reads can recover without reinitialization. browse uses 1-based pages of 50. subscribe/unsubscribe/download verify consumer game and ID; download priority false.
- Workshop items expose hasChineseContent (a text/tag heuristic), plus optional previewUrl (allowlisted HTTPS Steam CDN), updatedAt (Unix seconds), subscriberCount (safe nonnegative integer), and bounded tags. Missing/invalid metadata is omitted. browse validates categories and sort IDs against src/workshop-filters.json and forwards category/tags, excludedTags, matchAnyTag and trendDays to Steam. weekly uses native rank 3 with seven days, rated uses rank 0, dependencies rank 20 and collections rank 21; the last two use a lazy Windows x64 flat-API adapter inside the existing isolated worker and reuse its Steam session. The adapter uses bounded synchronous polling to avoid competing with the SDK callback pump, and releases each query handle. No SDK initialization occurs on offline reads.
- browse language accepts all/chinese/non-chinese. The two filtered modes identify Chinese from author titles, descriptions and tags, rather than Steam's localized-return language. Each request scans at most four source pages, targets 50 matches and stops after a 15-second soft scan budget; cursor:{page,offset} continues within the original Steam ordering. Filtered replies have languageFiltered:true, totalCount:null, totalPages:null, hasMore and nextCursor; the UI reports matches on this page without claiming a global filtered total. Untagged or unidentified Chinese may appear in non-Chinese results. Subscription filtering uses the same stored heuristic locally. Changing filters resets paging; the independent subscription rail and mutation confirmation boundaries are preserved. See docs/workshop-redesign.md.
- steam-workshop.repairItem({id,expectedSteamId}) is worker-only. It rechecks the connected Steam account and HOI4 App ID around asynchronous operations, reads uncached item details, rejects foreign/banned/unavailable items, subscribes only if needed, and requests download(id,false) only when not already current or downloading/queued. Returns {id,outcome,subscription,downloadRequest,observed,errorCode,error}; submitted/accepted never means that local files are installed. See docs/steam-missing-mods.md for result fields.
- steam-worker-client: optional Electron utility process isolates SDK; exits reject pending calls, write timeouts never auto-replay. A first connect timeout retires the worker only if no connection has succeeded and no mutation has been submitted; the next explicit connect creates a fresh process. repairItem activity remains reserved after RPC timeout until an explicit worker completion/late reply or process exit. While active, getState returns the cached state with repairing:true and conflicting writes/disconnect are refused. Startup/automated tests never initialize the real SDK.
- steam-missing: createSteamMissingService({storageDirectory,getLauncherState,steam,isGameRunning?,assertOperationAllowed?}) exposes prepare({playsetId}), commit(planId), getState(), cancel(), isBusy(), dispose(). prepare derives all missing Workshop members from the selected preset, including disabled members, without writes to Steam. Its review binds the account, ordered/enabled membership and game/user directories. commit consumes the review once, rechecks context and disk availability, persists a queued job and returns immediately; the worker processes items sequentially. Confirmed per-item failures remain visible and allow later items; unknown outcomes, actor changes, unavailable operation guards or persistence failure stop later submissions. cancel stops only later items, never rolls back an accepted native call. getState returns {job,plan}. Storage is steam-missing/missing-mods.json: v2 begins with one snapshot line, appends sequenced per-item intent/results and atomically replaces the same file with a final snapshot. Dynamic records exclude names/enabled flags; limits are 8 KiB per event and 256 MiB total. Intent is synced before RPC. Partial writes cannot be hidden by terminal compaction; incomplete tails and v1 records are preserved on read. Restart never replays requests: active jobs become interrupted, an in-flight item becomes unknown, and unsent items become cancelled. Preset order/enabled state are unchanged; only a later launcher disk scan can clear a missing reference. Named renderer methods are getSteamMissingMods(), prepareSteamMissingMods({playsetId}), commitSteamMissingMods(planId), cancelSteamMissingMods(), routed to steam-missing:state/prepare/commit/cancel.
- mod-thumbnails: replaces its ID registry from state scans, deduplicates matching in-flight reads and allows at most two concurrent readers. File/ancestor identities, size and timestamps are checked around reads; links, traversal, Windows aliases and source replacements fail closed. ZIP reads are lazy/bounded, CRC-checked and never extracted; limits are 100000 entries, 20 GiB archive and 64 MiB read budget. raster-image.validatedRaster(buffer) → {mime,width,height}|null enforces 8 MiB, 8192 pixels per edge and 16 Mi pixels. PNG/GIF have bounded structural/decompression checks; JPEG/WebP still require browser decode. The frontend lazily reads visible covers, shares per-scan results, keeps a static display copy capped at 512 pixels and falls back on any failure. See docs/mod-thumbnails.md for supported variants and GIF work limits.
- publish-service: getDraft(modId), prepare(input), commit(reviewId), cancel(), getStatus(), recordStatus(job), isPublishing(). Trusted local-mod resolution produces a bounded independent snapshot; final commit rechecks exact content and identities. History persists created Workshop IDs without rewriting the local descriptor. Interrupted/unknown writes are never replayed automatically.
- With provider:"pdx", publish-service uses separate publishing-pdx storage and adds refreshStatus() for read-only recovery. Review includes the account, short description and recommended version. Only the independent descriptor snapshot receives the recommended version. Active preparation/commit/recovery reserve the game-launch gate. Provider callbacks can persist during recovery without blocking on the same queue.
- pdx-publisher: getState(), validatePublishTarget(id), startPublish(input), getPublishStatus(), refreshPublish(job), dispose(). Owns account-bound V1 upload/publish/update and final revision checks. UUID and commit intent persist before remote writes; unknown results are not replayed. Actual service visibility is returned as job.visibility, with no promised default. See docs/pdx-publication.md.
- publish-archive builds reviewed files into a ZIP with root contents and deflate level 1; exact tree, identity/hash and final ZIP checks. Compressed package must be <5 GiB; application source budget is 200 GiB/100000 files. Cleanup retains foreign modifications.
- account-service.uploadFile({path,filePath,bytes,sha256,expectedAccountId,signal,onProgress}) is main-only with fixed HOI4 upload routes. It streams a verified file, creates a fresh body after one 401 renewal, rejects changes/early responses, and closes request/response streams and file handles. No generic upload IPC is exposed.
- Steam publication: validatePublishTarget(id), startPublish({id,existingItemId,contentPath,previewPath,title,description,tags,visibility,changeNote}), getPublishStatus(). Fast asynchronous submission with worker-pushed status; ownership and account identity are checked. A new item requiring agreement pauses before upload and preserves its ID. Active uploads prevent disconnect.
- account-service.bindSession({signal?,expectedAccountId?}) returns a main-only {accountId,signal,check,dispose} lease for one login. Logout, another login (including the same user), or session expiry cancels the lease; ordinary token renewal preserves it. It is never persisted or exposed over IPC.
- pdx-content: resolve({modId,revision?,expectedAccountId?,signal?,repair?:boolean}) returns a validated canonical complete plan; protected plans include access:"repository". Every resolve fetches the repository key, raw repository.json/manifest and their detached signatures, checks the fixed official root and fresh root/repository revocation state, then parses the verified bytes. It uses pdx-manifest but still requires exactly one ordinary ZIP entry; multiple targets or unsupported compression do not obtain download capabilities. Network manifests remain bounded to 64 KiB. Signed completeSize must equal the manifest ZIP size. Each resolved complete also receives a main-only ephemeral capability used for patch selection; serializing it loses that capability. download(plan,{destination,signal,pauseSignal,onProgress,onCheckpoint,bytesPerSecond,resume?:{source,checkpoint},resolvedPlan?}) streams to an exclusive new file. Protected plans and all patch plans require their matching capability before IO. Signed resource grants/URLs never enter checkpoint, journal or IPC. Awaited checkpoints persist a verified prefix with the actual transfer plan hash (including access and patch fields) and file/ancestor identities. Pause returns {paused:true,checkpoint,bytes}; success returns {path,bytes,sha256}. Resume copies only the trusted prefix, sends exact Range/If-Range, validates 206, restarts the same transfer from zero on 200, and rehashes final disk content. Without expectedAccountId only public/unlisted metadata is eligible; account mode reads the exact revision and authorizes every signed-metadata resource and ZIP separately. Both modes validate game/ID/revision/ACL/state/region/platform. Fixed account API; public content uses the fixed CDN, protected content only validated HTTPS domains granted by that API. No CDN credentials or redirects; strict size/hash checks. Denial never triggers guessed URLs, credential forwarding or fallback to another account. See docs/pdx-protected-repository.md and docs/pdx-signatures.md.
- pdx-repository: inert createPdxRepository({account,expectedAccountId,repositoryPath,now?}) exposes urlFor({revision,filename,signal?}) for complete manifest, manifest.asc and ZIP resources; urlFor({patch:{revision,fromRevision,filename},signal?}) for the canonical declared patch folder and its manifest, manifest.asc or ZIP; or urlFor({resource,signal?}) for exactly repository.json, repository.json.asc and \_keys/public.gpg. It additionally supports the exact content-addressed file form below. Root, complete, patch and file forms are mutually exclusive. Fixed HOI4 GET routes, independent resource grants, two-entry LRU and 60-second validity margin; TTL is Unix seconds. Only main process uses this helper. Session safety across cached grants depends on the coordinator's bindSession lease and signal; resume must resolve and verify anew.
- pdx-files repair strategy: the coordinator sets main-only repair:true only for repair jobs; this strategy stays in the ephemeral capability, never an IPC/checkpoint repair flag. Repair first requests files/<bytes>\_<padded-base64url-sha256>, derived from the verified complete manifest. pdx-repository accepts urlFor({file:{bytes,sha256},signal?}); fileResource(bytes,sha256) produces the exact logical resource. prepareRepair(plan,{resolvedPlan,signal}) selects a separately verified -1 installation patch only when the signed repository advertises -1 and the actual files content response is 404. A 200 keeps files-only transfer; a later failure stops. Repositories without -1 retain files→same-revision complete compatibility on actual content 404, with an independent grant. Grant denial, cancellation, redirects, authorization, network, length and hash failures do not trigger fallback or anonymous retry. A selected patch failure never silently retries complete. Existing Range, ETag, final hash and disk rehash guards remain. Manifest hashes accept canonical padded standard or URL-safe Base64, rejecting mixed alphabets and invalid trailing bits. See docs/cpatch-download-paths.md.
- pdx-integrity: getManifest({revision,fromRevision?,loadResource,lookupRevocation}) reads bounded raw byte snapshots, verifies both detached signatures before decoding/parsing, and requires repository format 0.3 plus the exact revision and numeric completeSize. Patch mode loads the exact fromRevision_to_revision manifest and validates declared packed/unpacked sizes, including a zero unpacked total for empty operations; packed ZIP size remains positive. It does not reuse the complete manifest signature as a patch signature. pdx-signature pins the production root fingerprint AF28077C9C565B53F3CD5A65788AA56D99D64E1C and root certification of the repository key. The narrow legacy key-expiry exception retains date, certification, signing-capability, binding/back-signature and revocation checks; SHA-1 is allowed only for legacy key certifications, while binary content signatures require SHA-256/384/512. Fresh revocation queries use the fixed production endpoint without credentials or redirects; 204 and the official legacy 404 mean no certificate, network/other failures stop, and a 200 certificate must contain exactly one target-primary-key self-signed revocation packet. Valid, forged or malformed revocation responses all stop the download. See docs/pdx-signatures.md.
- pdx patch selection: getPatchSize(plan,{resolvedPlan,fromRevision}) and resolvePatch(plan,{resolvedPlan,fromRevision,signal}) require the matching trusted complete capability. resolvePatch independently verifies repository/patch signed resources and fresh revocations, binds completeSize to the target, and checks patch packed/unpacked sizes against signed advertisement and manifest. Its canonical plan adds kind:"patch", fromRevision and unpackedBytes; the target binding remains ephemeral. A normal update selects a patch only when smaller than complete, the old complete is re-resolved/verified against the managed installation archive digest, and a fully verified original-ZIP cache lease is available. Before selection, unavailable cache/old-source optimization uses target complete; task/account cancellation and signed-metadata integrity errors still stop. After selection, any permission, signature, network, container, source or target failure stops without changing transfer type. A pinned patch resume must match both patch and old source again or retain fragments and fail.
- pdx-manifest: parsePdxManifest(input,{expectedName?,maxBytes=16MiB,maxEntries=100000,maxFileBytes=5GiB,maxTotalBytes=20GiB}={}) copies Buffer/string bytes, requires strict UTF-8, exact unique Name/Hash headers and sha256, and returns frozen {name,hashAlgorithm,entries}. Entries retain input order and flags; each has {path,type,bytes,sha256,flags}, with optional {unpackedBytes,compression} only when c is set. Types are file/directory/symlink; directories require bytes:0 and sha256:"", symlinks require bytes:0 and a valid digest, and empty ordinary files are allowed. CSV has exactly four or six fields, one physical line per record; only drwxcs flags are allowed, with d+s and d+c rejected. Canonical padded standard or URL-safe Base64 SHA-256 converts to lowercase hex; unknown compression remains inert data. Limits cover total input, 64 KiB lines, entry count, per-entry packed/unpacked and separate aggregate packed/unpacked totals. Invalid input yields fixed INVALID_MANIFEST or RESPONSE_TOO_LARGE errors. This parser does not verify signatures, revisions, actual files or authorization. See docs/pdx-patch-planning.md.
- pdx-patch-path: normalizePdxPatchPath(value,{directory=false}={}) converts backslashes and permits removal of one directory trailing slash, rejecting traversal, absolute paths, unsafe Windows names, isolated surrogates, replacement/control characters, trailing dots/spaces, device stems including spaced extensions, and path/segment/depth excess (1024 UTF-8 bytes / 255 bytes / 64). pdxPatchPathKey uses NFC→Unicode uppercase→NFC for conservative collision checks. Manifest and plan reject aliases and file/symlink ancestors, including implicit parent spellings. Normalization does not grant filesystem access; failures use INVALID_MANIFEST.
- pdx-patch-plan: parsePdxPatchOperations(Buffer|string) parses bounded UTF-8 rows using the exact colon-space delimiter into frozen operations, recognizing c/d/k/n/p/s; empty operations are valid. createPdxPatchPlan({operations,targets,sources=[],payloads=[]}) takes raw operations and typed manifest identities, returning frozen {deletes,directories,actions,operationCount}. Deletes are grouped with directoryPolicy:"empty-only"; directories include implicit parents in depth order; each non-directory target has at most one explicit producer or an implicit k requiring identical source type/bytes/sha256. Source-only surplus paths are not copied. n binds same-name payload length, p binds .vcdiff and a regular old file or empty source, s records a 1–4096-byte raw target payload without creating a link. Duplicate producers/deletes, aliases, invalid types, missing/unused payloads or source mismatches fail. Limits are 8 MiB operations, each row <64 KiB, 100000 rows/array entries/namespace nodes (implicit parents included), 5 GiB per file/payload and separate 20 GiB source/target/payload totals. Errors are INVALID_INPUT, PATCH_INVALID, PATCH_UNSUPPORTED, PATCH_RESOURCE_LIMIT, SOURCE_CHANGED or HASH_MISMATCH. It performs no IO, signature verification, payload hashing or filesystem scheduling/commit; recognizing six types does not enable general filesystem execution. See docs/pdx-patch-planning.md.
- pdx-patch-archive: applyPdxPatchArchive accepts private bounded patch/source/scratch/target byte callbacks and the trusted expectedTargetFilename/Bytes/Sha256. It validates the patch ZIP, entry paths/counts, sizes, compression ratio, CRC and bounded UTF-8 operations naming only that target ZIP, then uses the shared planner. The executable subset is at most one d plus one n/p/k; empty operations or d alone require a verified identical source and produce implicit k. n reads the target ZIP payload; p reads target.zip.vcdiff with a trusted old source or the empty-source SHA-256; k copies a verified source. d is logical against a fresh empty target handle and never deletes the old installation/cache. c/s, multiple producers/targets and extra payloads are rejected. Patch/source/target bounds are 5 GiB, operations 64 KiB, expanded total 5 GiB + 64 KiB, with at most eight preliminary ZIP entries and only one/two accepted entries; source and unpacked total may be zero. VCDIFF/XZ retain their own hard budgets. Final target is fully re-read and must equal the complete plan. It has no filesystem, network, authorization, commit or cleanup authority.
- pdx-patch-workspace: createPdxPatchWorkspace({directory,signal?}) accepts the coordinator's existing exclusive staging directory and returns frozen {openPatch,createScratch,createTarget,proofs,close}. Fixed files are patch.zip (fully hashed read-only), patch-data.bin and content.zip (wx+ sequential append). Files/ancestors, realpaths, size, timestamps and single hardlink are guarded around bounded IO; reads return exact Buffers up to 8 MiB and writes accept up to 64 MiB windows with 64 KiB internal blocks. Caller input is copied before yielding; failed writers cannot be reused. Target finish fsyncs and re-reads the full expected hash, returning numeric {ino,dev,birthtimeMs,size,mtimeMs,ctimeMs}. proofs() waits previous operations, blocks later IO/creation, hashes each current prefix against intended bytes and rechecks all identities, returning frozen [{name,bytes,sha256,identity}]. Cancellation is never ignored to manufacture cleanup proof. close is idempotent, releases handles even after cancellation, and can retry failed closes. This module never creates directories or deletes files.
- pdx-subscriptions: getState({refresh?}), subscribe({modId,revision?}), unsubscribe(modId). Returns {accountId,items:[{modId,title,revision?}],error?}; revision is an explicit pin, not latestVersion. Requests bind to expectedAccountId; ordered mutations deduplicate concurrent identical submissions. Structured errors distinguish writeSucceeded and outcomeUnknown; no automatic mutation replay. See docs/pdx-subscriptions.md for default-set and pagination evidence.
- pdx-file-integrity: create/verify/compare use a trusted extracted ZIP after descriptor sanitization, binding modId, revision and archiveSha256 to relative paths, sizes and SHA-256. Indexes remain under the fixed installer control root at indexes/<uuid>.json; each installation references {version:1,id,sha256,bytes}. Verification checks the index digest and binding before scanning installed files, returns intact/damaged/unverified plus missing/changed/extra/unsafe counts, and never follows links. Limits are 100000 entries, 20 GiB expected total, 4 GiB per file, 64 MiB per index and 100 returned issues. This is locally stored state derived from a verified ZIP, not an official signed per-file manifest. Failed/cancelled creation can retain an unreferenced index; no index garbage collection is implemented. See docs/pdx-repair.md.
- pdx-install: install({archivePath,plan,userDataPath,signal,onProgress,repair?:{installationId}}), verify(modId,{userDataPath,installationId,signal,onProgress}), list({includeDamaged?:boolean}), recover(), uninstall(modId,{userDataPath}). SHA-256 and ZIP CRC/size/path validation; links, traversal, Windows aliases and case collisions rejected. Records expose archiveSha256 and installationId. Default list requires matching content-root identity and registration, without scanning every file; includeDamaged:true also exposes recorded installations with changed/missing content root or registration as installationDamaged:true. verify performs file and registration checks against the exact managed installation. Repair pins the same revision and archive digest, preserves old content and a snapshot of an existing ordinary registration, and supports changed/missing registration with rollback/restart recovery. Unsafe or hard-linked foreign registrations fail closed. A healthy legacy install gains a trusted ZIP-derived index without replacing its files, registration or installationId. Transactional replacement changes installationId and preserves presets. See docs/pdx-repair.md.
- pdx-install relocation: planRelocation({userDataPath,targetParent:null|string}), relocate({planId,signal,onProgress}), getStorageState({userDataPath}), cancelRelocationPlan(planId). v2 database keeps control files and file-integrity indexes fixed while trusted content roots and per-userdir location selections change. v1 active records upgrade; unregistered legacy directories remain in place. Plans include current and verified retained version entries, byte/file totals, conflicts and retained paths. Copies are verified before transactional registration and database commit; matching old files are released, changed content retained. Recovery shares the original installer queue/disk lock.
- pdx-relocation coordinates reviewed plans and responsive progress with prepare/commit/cancel/discard/getState/recover/assertReady/isBusy/isBlocked/dispose. It binds the current game userdir and reserves mutations synchronously. Uncertain recovery remains blocked until explicit recovery succeeds; read-only replies cannot clear that gate. Startup and failed-cleanup retained paths remain visible. The actual installer journal, rather than a replayable UI job, determines restart recovery.
- pdx-downloads: getState(), start({modId,revision?,authorization?:"anonymous"|"account"}), repair({modId,authorization?:"anonymous"|"account"}), pause(), resume(), cancel(), setLimit(bytesPerSecond), uninstall(modId), isBusy(). getState returns {job,installations,bytesPerSecond}; job includes canPause/canResume/canCancel and may be verifying/pausing/paused. Repair derives the current user-directory installation, revision and installationId in main, rejecting renderer-supplied paths, revision or installation identity. A healthy anonymous repair check performs no network IO; account mode first validates the login session, but a healthy check requests no content metadata, signed resources or ZIP. The local verifying phase permits cancel but not pause. Missing/unusable legacy indexes require a newly verified same-revision ZIP; damaged installs use the original transaction and retain old content. Anonymous is the default. Account mode obtains the current account lease in the main process and binds metadata, CDN transfer and installation to its signal; the renderer cannot supply an account ID or token. Only the chosen mode persists, never a reusable authorization. resume accepts no arguments and rebinds the current session, user directory and exact pinned plan; repair also rechecks its installationId. Reopening never contacts the content provider automatically. Paused/held fragments block new tasks until explicit resume or cancel; installation cannot pause, and its transaction determines the commit outcome. The v2 journal stores {job,bytesPerSecond,staging,partial,resumeSource}; repair jobs also retain operation and installationId, while v1 unverified fragments are preserved without resuming. A replacement checkpoint is saved before old-source cleanup; every intermediate journal is independently loadable. Progress reads remain responsive during installation. 0 means unlimited; maximum 1 GiB/s. Staging cleanup requires recorded identities and prefix hash; unknown tails and external modifications are retained in retainedDownloadDirectories (legacy first path: retainedDownloadDirectory). See docs/pdx-resume.md and docs/pdx-repair.md.

## Desktop boundary

Main injects an inert `createPdxArchiveCache({storageDirectory:<userData>/pdx/archives})` into downloads. After a verified complete transfer or reconstructed target and before installation, downloads optionally `put(plan,{sourcePath,signal})` with combined account/task/pause cancellation. Cache budget/storage errors skip saving; cancellation, pause and account changes still stop installation. Patch source selection opens only a fully verified original-ZIP lease after independently re-resolving the old complete. No installed-directory recompression or official cache reuse occurs. Installation revalidates its own target ZIP and transaction. No cache path, lookup or codec capability crosses IPC; exact interfaces and hard limits are documented in [pdx-delta-core](docs/pdx-delta-core.md).

The v2 download journal separates target partial.plan, optional actual patch partial.transferPlan and optional old complete partial.sourcePlan. Checkpoint planKey always binds transferPlan || plan, including kind/fromRevision/unpackedBytes; unpackedBytes:0 is preserved as a meaningful signed value for empty-operation ZIPs, never a zero-length target or transfer. Patch downloads use patch.zip and decoded targets use content.zip. A -1 installation patch has no sourcePlan. Resume re-resolves target, patch and required old source, rechecks signatures/access/cache identities and copies only the matching prefix. A changed selected patch or missing old cache retains fragments instead of switching to complete. After target finish, workspace proofs for scratch/target are persisted as staging.artifacts; cleanup independently rehashes and rechecks recorded identities, while the transfer file retains its original checkpoint/identity proof. Unknown files, tails, crash/cancel products without proof and external changes are retained. Only the fully verified target complete plan enters the original installer transaction; old content, registration backups and preset state remain protected by that transaction.

preload exposes named methods, never generic invoke/filesystem/network/SQL/provider calls. repairPdxMod(input) invokes only pdx:repair with modId and authorization. Main validates sender and main frame. Native dialogs wrap JSON exchange/diagnostics; external links use allowlisted destinations or numeric mod IDs. Sandbox/context isolation/web security remain enabled; navigation/popups/permissions denied. Diagnostics omit tokens and raw IPC input. Game launch and active publication/download/validation/installation exclude each other. Account providers can bind a request to expectedAccountId before any authenticated network call; account changes invalidate outstanding request epochs.

Explicit localized errors keep the legacy message and may carry a bounded diagnostic tree: message {key,values}, sequence {parts}, or literal {text}, each tagged by kind. Only own keys from the bundled English catalog are accepted; string/finite-number values are literal. Limits are depth 8, 128 nodes, 8192 total input characters and 64 items per array. Invalid/oversized metadata falls back to the legacy message. Main normalizes metadata and returns a private \_\_ironcladDiagnosticError:1 envelope with message, diagnostic and optional uppercase code; preload unwraps it into a rejected Error, preserving named-method rejection semantics despite Electron stripping custom Error fields. No generic channel is exposed. News/catalog/relocation/publication state uses optional errorDiagnostic beside error; original schemas and strings remain compatible. The renderer translates only explicitly marked nodes and preserves user/remote literals; it does not recursively infer arbitrary text. See docs/launcher-i18n.md.

diagnostics:export defaults to IRONCLAD-diagnostics.zip, with a JSON filter retained. A selected .json extension (case-insensitive) keeps the JSON report; other filenames receive a ZIP containing diagnostics.json, events.jsonl and generated logs/history-NNN.jsonl entries. After save approval, one diagnostics-log snapshot is added as logHistory; both formats serialize that explicit data. The archive helper reads no paths, official logs, account stores or player files. The live ring retains 200 events. Account event messages are omitted; other summaries redact common credential patterns, with no claim of universal free-text detection. Cancellation writes nothing; export write failures reach the caller. Paths and warning text retain their original language.

diagnostics-log exposes createDiagnosticsLog({storageDirectory,maxFileBytes?,maxFiles?,maxPending?,deadlineMs?,fileOps?,now?}) and sanitizeDiagnosticEvent(raw). Construction performs no IO. record(event) synchronously returns queue acceptance; it never waits for persistence. flush()/close() return status; snapshot() returns {schemaVersion:1,directory,limits,status,files:[{name,sessionId,part,createdAt,events,truncated}]}. Defaults are hard upper limits: 2 MiB per file, 3 files, 64 unfinished events and 2000 ms per wait. Queue overflow increments droppedEvents. A complete write is synced; flushed complete records survive restart, while unsynced/queued records may be lost. New instances create new UUID sessions, retaining only verified managed logs; complete corruption or unsafe identities disable persistence and preserve evidence. Truncated final lines are skipped and remain eligible for ordinary retention. Reads and enumeration are bounded. IO failure/timeout never fails an ordinary business IPC. Normal will-quit is prevented once, then reissued after the bounded close settles. Full behavior and verification are in docs/diagnostics.md.

Steam missing-mod submissions reserve the same game-launch/file-operation gate as other active mutations; an RPC timeout does not release a native call still in progress. The renderer cannot choose repair item IDs or an account directly: it receives a main-process review and submits only its planId. Reading persisted results does not initialize Steam or replay mutations.

The official speed-limit menu applies to CPatch only. Steam speed and pause remain controlled by the Steam client; no per-item Steam throttling/pause API is promised. IRONCLAD's own authorized PDX complete/patch limits and resume state are independent of CPatch. The product is a local portable launcher without self-update.
