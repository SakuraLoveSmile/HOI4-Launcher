# 战役与模组工作流改进

按用户指定顺序实施；本文件同时记录接口、验收与交付证据。

| 顺序 | 目标                                   | 负责人和范围                                                    | 完成标准                                                                                                              |
| ---- | -------------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 1    | 战役档案、配置变化提醒、存档备份和备注 | 主代理：战役服务、IPC、界面；子代理：独立环境指纹模块与专项测试 | 本地存档绑定完整环境；重开保留；相同版本但内容改变可识别；继续前审阅变化；备份与恢复保护现存文件；隔离服务/界面验证   |
| 2    | 整套 Mod 组合的稳定内容快照            | 主代理集成现有项目检查点和播放集                                | 原版/Steam/PDX/本地项目的启用组合保留实际内容；恢复为独立播放集，原内容不覆盖；摘要校验、失败保护、重开恢复及界面验证 |
| 3    | 有证据的跨 Mod 覆盖检查                | 主代理；模块可独立委派                                          | 同路径文件、replace_path、重复事件/国策标识可追溯到 Mod/文件/行；不推断必需前置或必然不兼容；有界扫描/取消/错误显示   |
| 4    | 游玩资源占用对比与配置差异             | 主代理；独立统计部分可委派                                      | 两次游玩可比较 CPU/内存曲线、摘要、配置差异与备注；旧记录可读；缺测不补零；不把占用等同游戏推进速度                   |
| 5    | 可持久化的紧凑首页                     | 主代理                                                          | 可切回完整首页；首屏包含继续战役、当前组合、变化与最近游玩；1000px布局和重开偏好验证                                  |

主代理始终负责集成和最终验证；并行编辑只分配不重叠文件。实现顺序保持 1→2→3→4→5，先行的独立模块仅为当前项提供基础。

## 数据与操作边界

- 新记录独立存放在 IRONCLAD 应用数据目录；原设置、播放集、本地项目沿用现有格式。
- 存档只从当前实例的 `save games` 原生选择，拒绝路径逃逸和链接。存档恢复先备份当前内容；不操作 Steam Cloud。
- 配置恢复与 Mod 内容恢复分别展示。仅内容快照承诺保存字节；Steam 订阅名单不等于旧版保留。
- 扫描和比较只读；备份/恢复和项目操作与启动、下载、发布互斥。失败保留可恢复文件并给出操作入口。
- 现有 12 种界面语言及具名 IPC 边界继续遵守。测试只使用独立目录、替身网络与进程，不接触真实游戏、存档或账号。

## 组合快照接口与流程

模组管理工具栏的“组合快照”用于当前启用集合。保存内容、外部登记描述文件和完整环境；停用成员只保留顺序及引用。目录/ZIP、已有本地项目与其固定检查点沿用扫描得到的实际内容源。

原始快照独立保存在 `playset-snapshots/<UUID>/`。只有源的前后核验、复制及副本摘要全部通过后，才提交 `snapshot.json`，界面才将其列为完整快照。未完成目录保留并显示；不会覆盖源模组或把工坊订阅当作版本保留。

恢复先核验保存的文件，再通过现有项目服务创建独立本地项目，将其可玩版本固定到一个新播放集。逐项创建状态写入恢复记录，重开后可继续核验和复用；最后一次设置提交才切换播放集。原模组、原播放集、原始快照始终保留。项目的发布身份字段按既有规则移除，外部登记中的游戏语义字段保留。快照不含游戏本体或存档；游戏版本不同会在恢复确认中提示。

UI 和 IPC 已接入；新增两项主进程检查覆盖快照操作与启动/设置/版本切换的互斥，以及按记录 ID 打开目录。第 2 项接入后的既有播放集 UI 40 项、通用界面 54 项通过，日志分别为 `step-2-playsets-ui.log` 和 `step-2-general-ui.log`。最终快照专项 24 项通过，见 `step-2-snapshots-final.tap`；单文件上限沿用本地项目的 4 GiB，每 Mod 总计 20 GiB/100000 项，组合总计 100 GiB/200000 项。超限在提交完整记录前拒绝，不生成无法恢复的完整快照。

## 跨 Mod 覆盖检查

主代理负责 `ModCoverage.jsx`、IPC、界面验收；子代理只编辑 `mod-coverage.cjs`、其专项测试和 `mod-project-checks.cjs` 中追加的纯解析接口。翻译代理仅维护既有 11 份语言目录。

扫描从可信当前播放集选择实际启用内容，读取同路径文件、外部登记描述中的 `replace_path` 和语法中的事件/国策定义。结果按播放集列表次序展示来源，不推断最终加载胜出方或必需前置。扫描/证据仅通过生成的报告与证据 ID 访问，渲染器不能提交任意文件路径。缺失、无法读取或超限内容显示未完整检查；配置或证据文件变化后要求重新扫描。

第 3 项已通过 113 项相关 Node 检查、13 项真实服务 UI 和 7 项生产 preload 隐藏 Electron 检查；证据为 `step-3-node.tap`、`coverage-ui.json` 和 `step-3-desktop-final.log`。独立复核发现的共享国策和 CR 单字符换行漏检已修复并补回归。界面可读取文件/行与转义文本，来源或登记描述变化时拒绝旧证据；缺失启用项明确显示部分检查。目录和 ZIP 均有路径/条目/文本/解压/显示预算，扫描可取消。

隐藏 Electron 首轮功能断言已全部通过，但进程内清理 Chromium 目录等待过久；测试改为父进程在 Electron 退出后清理后，完整流程退出码 0。首次目录 `<用户目录>/AppData/Local/Temp/ironclad-workflows-desktop-<随机标识>` 的单独清理被自动审批以 `blocked by policy` 拒绝，保留该测试目录；本轮后续临时目录正常由测试父进程清理。

## 游玩比较

第 4 项已通过 175 项相关 Node 检查、18 项真实服务对比 UI、28 项原统计 UI 和 9 项生产 preload 隐藏桌面检查；证据为 `step-4-node.tap`、`performance-comparison-ui.json`、`step-4-performance-regression.log` 与 `step-4-desktop.log`。其中环境／备注专项 23 项，与原统计 30 项一起覆盖采集器实际重写摘要后的 sidecar 字节保留、外部写入、损坏原件和恢复失败。

两次记录按启动后的经过时间叠图，缺测不补零，较短记录范围外不显示采样；摘要 B−A 使用百分点和 GiB。完整环境与备注独立保存，旧记录仍可读。普通启动记录实际配置但不深度核验 Mod 内容；界面明确显示未知内容与无法比较的旧环境，不将资源占用差异称为游戏推进速度。

## 紧凑首页

第 5 项已通过 27 项真实服务／预览界面检查，覆盖 1000×900 首屏、服务与界面重开、语言切换、缺失存档、两项独立读取失败与恢复、迟到响应及切回完整首页。主代理拥有 `CompactHome.jsx`、布局及测试；翻译代理仅编辑 11 份词典。完整首页保持默认，`launcherPreferences.homeLayout` 仅接受 `full|compact`，缺字段的旧配置不强加新默认值。切换语言与关闭偏好保留布局，界面偏好不进入游戏环境差异。

紧凑首页集中继续战役、当前组合、配置摘要与当前实例最近三次游玩；优先选择继续存档对应的已绑定档案，保留档案选择器、播放集和启动模式切换。继续经过已有完整审阅。首页摘要只比较配置选项，明确提示尚未核对实际文件；战役和统计独立读取与报错，过期请求不能覆盖新配置结果。

独立复核发现的部分档案损坏后降级绕过审阅已修复：紧凑首页在无档案且扫描有遗漏时禁止继续，完整首页的 `reviewCurrent` 同样拒绝不完整结果；有效匹配档案仍可正常审阅。后台 10 项战役专项与真实损坏记录 UI 均验证此路径。早期 UI 脚本的精确文本选择器、重开夹具服务引用和设置页账号桩遗漏也已修正，失败日志保留；最终 `step-5-compact-ui-release.log` 为 27/27。
