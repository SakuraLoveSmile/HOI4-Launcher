# 诊断与会话日志导出 · 0.12.0

设置页的「导出诊断」默认保存 `IRONCLAD-diagnostics.zip`，对应官方启动器的 ZIP 日志导出能力。保存对话框也提供 JSON 类型；选择以 `.json` 结尾的文件名时导出原有 JSON 报告，大小写均可。取消对话框不写文件；保存失败会返回错误。

## ZIP 内容

- `diagnostics.json`：生成时间、启动器/运行时版本、游戏识别结果、路径、模组/预设/DLC 数量、启动状态、扫描提示、会话事件及 `logHistory`。
- `events.jsonl`：同一份会话事件，每行一个 UTF-8 JSON 对象。事件内部的换行会编码为转义字符，保留一行一条记录的格式。
- `logs/history-001.jsonl` 等：同一份 `logHistory.files` 快照中的已验证事件，每个文件以版本化头部开头。名称由归档器生成，不使用报告里的路径读取文件。截断尾部只保留完整记录，`truncated` 标记在报告中。

内存会话事件保留最近 200 条，记录时间、操作、结果及最多 1,000 字符的错误摘要。账户操作只保留时间、操作和结果，省略自由文本错误；其他摘要过滤常见密码、令牌和认证字段。写入与历史读取共用规范化函数，只保留 `at/action/result/detail`，不记录原始 IPC 参数或账户存储。报告仍保留路径、扫描提示和用户内容，界面语言切换不会翻译这些原文；模式过滤不保证识别所有自由文本中的敏感信息。

## 跨重启日志

主进程在自身 `%APPDATA%/IRONCLAD/logs/` 保存 `session-<uuid>-<part>.jsonl`。每次运行使用新会话，不向旧文件追加。受管文件最多 3 个、每个最多 2 MiB；跨会话和同会话分片按创建时间/分片顺序保留最近内容。已验证的截断日志也遵循正常轮换限制，不无限保留；未知文件不会删除。文件名匹配但头部或完整记录损坏时，保留原件并停止本次磁盘日志，导出可用内存事件及明确故障状态。

记录通过串行后台队列写入，最多接收 64 个尚未完成的事件；容量满时计入 `droppedEvents`。完整写入并同步后才视为落盘，普通 IPC 不等待磁盘。导出等待前序记录并读取一次快照，JSON 和 ZIP 使用同一份数据。`logHistory.status` 提供 `available/reason/closed/droppedEvents/writeFailures/issues`；超时为 `reason: "timeout"`，不会伪装为持久化成功。正常退出会取消首次 `will-quit`，等待日志关闭后重新退出，最长等待 2 秒。

异常终止前已同步的完整记录可在重开后读取，最后排队中的事件可能丢失；不完整末行（包括未写完的 UTF-8 字符）跳过并标为截断。日志不是业务事务凭据。磁盘权限、空间不足、链接、硬链接或文件/目录身份替换会停止持久化，应用业务仍可继续。每次读取限制文件大小、目录条目（128）、每行字节和记录数，不追随目录联接或符号链接，不自动修复或清空异常目录。

`electron/diagnostics-archive.cjs` 只将主进程明确构造的报告与事件放入内存 ZIP。报告里的路径作为文本保存，不据此收集文件，不读取官方启动器日志、账号存储或玩家文件，也不调用外部压缩程序。内容由已有 `yazl` 依赖打包，无新增依赖。

## 验证范围

`tests/diagnostics-log.test.cjs` 用隔离目录与可注入文件系统检查跨实例/系统 Node 进程退出后的恢复、轮换、截断和损坏、链接及身份替换、短写/同步失败、容量、挂起超时、关闭、脱敏与快照隔离。`tests/diagnostics-archive.test.cjs` 检查真实 ZIP 解码、中文/换行、完整报告、空事件、安全历史名称及序列化失败。`tests/main-migration.test.cjs` 使用实际主进程源码及隔离原生/文件系统替身，检查 ZIP 默认类型、JSON 兼容、单次历史快照、故障状态、原文保留、账户错误排除、取消、保存失败和退出等待。

这些检查不启动 Electron、官方启动器、游戏或真实账户。新版桌面运行验收仍待完成，最终结果以 [ROADMAP](../ROADMAP.md) 的本轮记录为准。
